# PLC 可选字段与现场协议适配设计

日期：2026-07-24

## 背景

普通测试 PLC 的字段偏移配置目前由 `plc_field_offset_table` 持久化，并由
`PlcFieldOffsetDialog`、`PlcService`、配置保存回传和测试结果回传共同使用。

现有实现存在以下问题：

1. 字段偏移弹窗只允许 `current_value_offset` 为空，其余字段全部要求填写，
   因而无法适配现场 PLC 中不存在“返回 SN”“返回机种”等字段的情况。
2. 现场 PLC 的异常码字段是 Siemens `Int`，现有代码却按 `String` 写入，
   会产生错误的数据布局，并可能覆盖后续字段。
3. 现有字符串读取固定申请 256 字节，字符串写入固定按 254 字节构造，
   无法安全适配客户修改过的 Siemens `STRING[N]` 长度。
4. 现场 PLC 包含“转速值”和“测试中”字段，现有偏移模型、配置界面和通信
   服务均未定义这两个字段。
5. 空字段的跳过逻辑分散在各读写路径中，缺少同一套字段类型、必填规则和
   方向约束，容易出现界面允许保存但运行时仍按错误类型处理的情况。

## 目标

- 仅把启动信号设为必填；其他普通测试 PLC 字段全部支持留空。
- 空偏移不会阻止连接、启动检测、工单读取、配置回传或结果回传。
- 现场 PLC 字段类型是唯一协议来源，不保留旧 PLC 的错误类型兼容。
- 支持可选的转速读取和测试中状态回传。
- Siemens 字符串长度从 PLC 字符串头动态识别，不把 SN 或型号长度写死。
- 在不改写已有偏移值的前提下，为新增字段提供可重复执行的数据库迁移。
- 保持工艺 PLC 的独立连接与工艺参数偏移逻辑不变。

## 非目标

- 本次不把 PLC 转速接入声音、振动、STFT 或评分算法。
- 本次不改变 PLC 与测试配置的绑定规则。
- 本次不批量替换现有 PLC 记录中的地址值。
- 本次不修改配置包格式，也不把普通 PLC 连接配置打包进 `.dy` 配置包。
- 本次不兼容旧 PLC 中按 `String` 表示异常码的协议。
- 本次不增加任意自定义 PLC 数据类型编辑器；字段的数据类型由软件协议定义。

## 现场协议

目标现场表表达的字段如下。除启动信号外，所有字段的偏移都可为空。
表中的示例偏移只用于说明现场布局，不作为数据库迁移时自动写入的默认值。

| 逻辑字段 | 方向 | Siemens 类型 | 示例偏移 | 必填 | 运行时行为 |
| --- | --- | --- | --- | --- | --- |
| `start_signal_offset` | PLC → PC / PC 复位 | `Bool` | `0.0` | 是 | 检测上升沿；接受后按现有策略复位 |
| `current_value_offset` | PLC → PC | `Real` | `2.0` | 否 | 采集电流；为空时不采集 PLC 电流 |
| `rotation_speed_offset` | PLC → PC | `Int` | `6.0` | 否 | 读取到 PLC 工单上下文，暂不参与分析 |
| `res_testing_signal_offset` | PC → PLC | `Bool` | `8.0` | 否 | 测试真正启动后置位，结束或中止时清零 |
| `res_finish_signal_offset` | PC → PLC | `Bool` | `8.1` | 否 | 结果字段成功处理后最后置位 |
| `res_error_code_offset` | PC → PLC | `Int` | `10.0` | 否 | 写入 16 位有符号异常码 |
| `res_result_offset` | PC → PLC | `Bool` | `12.0` | 否 | 写入 OK/NG |
| `res_score_offset` | PC → PLC | `Real` | `14.0` | 否 | 写入评分 |
| `res_spl_offset` | PC → PLC | `Real` | `18.0` | 否 | 写入声压结果 |
| `res_loudness_offset` | PC → PLC | `Real` | `22.0` | 否 | 写入响度结果 |
| `res_vibrate_data_offset` | PC → PLC | `Real` | `26.0` | 否 | 写入振动结果 |
| `res_ai_score_offset` | PC → PLC | `Real` | `30.0` | 否 | 写入 AI 评分 |
| `res_spl_limit_up_offset` | PC → PLC | `Real` | `34.0` | 否 | 配置保存后回传 |
| `res_spl_limit_down_offset` | PC → PLC | `Real` | `38.0` | 否 | 配置保存后回传 |
| `res_loudness_limit_up_offset` | PC → PLC | `Real` | `42.0` | 否 | 配置保存后回传 |
| `res_loudness_limit_down_offset` | PC → PLC | `Real` | `46.0` | 否 | 配置保存后回传 |
| `res_vibrate_limit_up_offset` | PC → PLC | `Real` | `50.0` | 否 | 配置保存后回传 |
| `res_vibrate_limit_down_offset` | PC → PLC | `Real` | `54.0` | 否 | 配置保存后回传 |
| `res_ai_score_limit_down_offset` | PC → PLC | `Real` | `58.0` | 否 | 配置保存后回传 |
| `sn_code_offset` | PLC → PC | Siemens `STRING` | `62.0` | 否 | 动态识别长度并读取 SN |
| `product_model_offset` | PLC → PC | Siemens `STRING` | `80.0` | 否 | 动态识别长度并读取型号 |
| `res_sn_code_offset` | PC → PLC | Siemens `STRING` | 无 | 否 | 现场不存在时留空；配置后动态识别长度写入 |
| `res_product_model_offset` | PC → PLC | Siemens `STRING` | 无 | 否 | 现场不存在时留空；配置后动态识别长度写入 |

`Int` 在本设计中指 Siemens S7 的 16 位有符号整数，使用
`snap7.util.get_int` / `snap7.util.set_int` 进行转换。

## 集中字段协议

应建立一份普通测试 PLC 字段描述表，至少声明：

- 字段键；
- 用户可见标签；
- Siemens 数据类型；
- 方向；
- 是否必填；
- 是否进入启动工单、配置回传或结果回传。

偏移弹窗、偏移读取、PLC 值编解码、配置回传和结果回传必须引用同一份字段
描述，不能继续各自维护不一致的字符串集合或类型映射。

字段描述是代码协议，不写入数据库。数据库仍只保存每个 PLC 的可空偏移值。

## 偏移配置界面

### 校验规则

- `start_signal_offset` 为空时拒绝保存，并聚焦该输入框。
- 其他任意字段为空时允许保存为 `NULL`。
- 非空偏移必须符合 `字节.位` 的现有格式。
- `Bool` 偏移的位部分必须在 `0..7`。
- `Int`、`Real` 和 `STRING` 字段使用字节偏移；界面仍接受现有的 `N.0`
  表示方式，以避免改变用户输入习惯。

### 字段呈现

- 新增“转速值 RotationSpeed”和“返回测试中 ResTestingSignal”输入项。
- 现有“返回 SN”“返回机种”等字段继续显示，但允许留空。
- 不在界面中要求用户填写 Siemens 字符串最大长度。

## Siemens 字符串动态长度

### 读取

对任意已配置的 Siemens `STRING` 字段：

1. 先从字段字节偏移读取两个头字节。
2. 第一个字节是 PLC 声明的最大长度，第二个字节是当前长度。
3. 最大长度必须大于零，当前长度不得大于最大长度。
4. 当前长度为零时返回空字符串。
5. 只继续读取当前长度个数据字节，不固定读取 256 字节。
6. 使用 ASCII 解码并沿用现有的容错策略处理不可解码字节。

### 写入

对任意已配置的 Siemens `STRING` 回传字段：

1. 先读取目标地址的两个头字节，取得 PLC 声明的最大长度。
2. 最大长度无效时，本字段写入失败并记录明确日志，不猜测长度。
3. 待写文本超过最大长度时，本字段写入失败并记录明确日志，不静默截断。
4. 按 PLC 声明长度构造 `最大长度 + 2` 字节的 Siemens 字符串并写入。

该机制使客户将 SN 或型号改为其他 `STRING[N]` 长度时无需修改软件字段配置。

## 启动与“测试中”生命周期

PLC 上升沿只表示提出启动请求，不等同于测试已经启动。`ResTestingSignal` 必须
跟随工厂模式实际接受的 PLC 测试生命周期：

1. `PlcService` 检测启动上升沿，读取可用的 SN、型号和转速并发出 PLC 启动请求。
2. 工厂模式完成配置匹配和运行前校验。
3. 后端测试会话真正接受启动回调后，通过带 `plc_id` 的 PLC 状态写入信号，
   请求对应 `PlcService` 写 `ResTestingSignal=True`。
4. 被拒绝、没有匹配配置或启动失败的请求不得置位“测试中”。
5. 自动分析成功、无结果、分析异常或正常停止时写
   `ResTestingSignal=False`。
6. 后端运行中止时也必须写 `False`，即使没有生成完整测试结果。
7. 未配置 `res_testing_signal_offset` 时，上述状态信号仍可发出，但
   `PlcService` 安全跳过 PLC 写入。

应由工厂模式保存当前 PLC 运行的 `plc_id`，以便停止和中止路径能够清除正确
PLC 的“测试中”状态。手工触发、扫码触发和导入音频不得写该状态位。

## 工单读取

启动上升沿后，`PlcService` 尝试读取以下可选字段：

- SN；
- 产品型号；
- 转速值。

成功读取的值加入 PLC 工单；空字段、空字符串或单个可选字段读取失败不阻止
启动请求。转速以整数形式进入工单上下文，但本次不将其传给分析算法。

启动信号本身读取失败仍按现有连接故障处理，因为它是唯一必填字段。

## 配置回传

保存测试配置后，现有机种和阈值回传流程继续按绑定的 `plc_id` 路由。

- 每个回传字段先检查偏移是否存在。
- 偏移为空时跳过该字段，不输出“配置缺失”警告。
- 非空字段按集中协议中的类型写入。
- `res_product_model_offset` 若存在，按动态 Siemens 字符串长度写入。
- 一个字段的数据转换或 PLC 写入失败时记录字段名、PLC id 和原因。
- PLC 连接故障仍按现有连接错误路径处理。

## 结果回传

结果回传按以下顺序处理：

1. 把 `ResTestingSignal` 清为 `False`。
2. 逐项写入已配置的异常码、可选返回 SN、测试结果、评分、声压、响度、
   振动和 AI 评分。
3. 仅在所有已配置的结果字段均成功处理后，最后写
   `ResFinishSignal=True`。

缺失偏移视为“该字段未参与协议”，不视为错误。非空偏移发生数据转换或 PLC
写入失败时，不写结束信号，避免 PLC 将不完整结果视为完成；同时记录明确日志。

异常码 payload 必须在写入边界转换为 16 位有符号整数。无法转换或超出
`-32768..32767` 时，本次结果回传失败且不写结束信号。

## PLC 值编解码

`PlcService` 的通用读写边界应支持：

- `Bool`：读改写单个 bit；
- `Int`：两字节 Siemens 有符号整数；
- `Real`：四字节 Siemens REAL；
- `STRING`：使用 PLC 头部动态长度。

调用方不再传递任意字符串形式的类型名称；类型由字段协议查得。若保留底层
通用编解码帮助函数，其公开输入必须是受控类型值，并对无效类型明确失败。

## 数据库与迁移

`plc_field_offset_table` 增加两个可空 `TEXT` 列：

- `rotation_speed_offset`
- `res_testing_signal_offset`

迁移要求：

- 执行前备份数据库文件；
- 仅增加缺失列；
- 新列默认 `NULL`；
- 不修改任何已有偏移；
- 在一个事务中执行；
- 可重复运行；
- 表不存在时拒绝迁移且不进行部分变更；
- 启动 schema 门禁把两个新列列为必需列。

运行数据库是外部预置产物，因此交付时需要对权威预置数据库运行迁移。应用
启动时不自动修改数据库 schema。

## 错误处理与日志

- 缺失的可选偏移是正常配置，不记录 warning。
- 非法的必填启动偏移在界面保存时阻止。
- PLC 字符串头无效、文本超长、Int 转换失败或地址读写失败时，日志包含
  PLC id、字段键和失败原因。
- 读取某个可选工单字段失败时继续处理其他字段和启动请求。
- 结果写入失败时不写结束信号。
- 状态清零失败时记录错误；后续停止、中止或结果路径再次清零应保持幂等。

## 测试策略

### 配置界面

- 只有启动信号为空时校验失败。
- 每个其他字段单独为空时均可保存。
- 非空非法偏移仍被拒绝。
- Bool 位索引超出 `0..7` 时被拒绝。
- 新增字段能够加载、编辑和保存。

### PLC 编解码

- `Int` 正数、负数、边界值可正确读写。
- 异常码不再使用字符串写入。
- 不同 `STRING[N]` 的头部可动态读取。
- 空字符串、非法头部和超长写入按设计处理。
- 字符串读取不会固定申请 256 字节。

### 可选字段

- 只配置启动信号时仍可连接并触发测试。
- 电流、SN、型号、转速、测试中、结果和阈值字段分别缺失时均不会出现
  `KeyError` 或阻断其他路径。
- 空配置不会产生误导性的“未找到偏移配置”警告。

### 生命周期

- PLC 启动被真正接受后写“测试中=True”。
- 启动被拒绝时不写 True。
- 成功、无结果、分析错误、停止和中止都写 False。
- 手工、扫码和导入音频不会写 PLC 测试中状态。
- 结果字段先写、结束信号最后写。
- 任一已配置结果写入失败时不写结束信号。

### 迁移

- 首次迁移创建备份并增加两列。
- 重复迁移不重复增加列。
- 已有 PLC 行和偏移值保持不变。
- 事务失败时两列均不留下部分变更。
- 缺少目标表时数据库内容不变。

## Compatibility / Migration

- Backward compatibility: not required
- Protected surfaces: [现场 PLC 新协议、普通测试 PLC 启动检测、PLC 与测试配置绑定、配置回传、结果回传、工厂模式非 PLC 触发路径、工艺 PLC]
- Allowed breakage: [旧 PLC 的字符串异常码协议、固定 254/256 字节字符串处理、缺少新增偏移列的未迁移数据库]
- Migration strategy: migration script

旧 PLC 协议不提供兼容层。已有偏移值会保留，但部署数据库必须先通过迁移增加
新列；现场人员再按实际 PLC 表配置需要的非空地址。

## 验收标准

1. 偏移配置只要求启动信号，其他所有字段可为空并可保存。
2. 只配置启动信号的 PLC 能正常连接、检测上升沿并发出启动请求。
3. 现场异常码以 Siemens `Int16` 写入，后续字段不被字符串写入覆盖。
4. SN、型号及可选字符串回传能适配客户修改后的 `STRING[N]` 长度。
5. 转速可选读取并进入 PLC 工单，但不改变分析结果。
6. PLC 触发测试被接受后“测试中”置位；所有完成、失败、停止和中止路径清零。
7. 配置与结果回传跳过空字段；结果字段失败时不写结束信号。
8. 两个新增偏移列可通过有备份、幂等、事务化迁移加入，且不改写现有偏移。
9. 工艺 PLC、手工触发、扫码触发和导入音频行为无回归。
