# PLC 扭矩读取、查表回传与 Excel 导入

日期：2026-09-10
状态：设计文档评审已通过；用户已于 2026-09-10 回复“OK”确认，可进入实施规划。

## 目标与已确认的业务规则

常规生产由软件维护型号或 SN 对应的扭矩表。试产等尚未维护扭矩表的场景，客户可以直接在 PLC 上输入扭矩。扫码和 PLC 程序由客户负责，软件复用现有 PLC 开始测试入口。

每次收到现有开始信号时，软件沿用当前启动测试流程，并处理该 PLC 的扭矩：

| 读取地址的值 | 本次扭矩来源 | 回传行为 |
| --- | --- | --- |
| 有限浮点数且等于 0 | 软件扭矩表 | 按已配置的型号或 SN 查表，成功则写入回传地址 |
| 有限浮点数且不等于 0 | PLC 输入 | 采用读取值，仅显示，不使用软件表覆盖，也不回写该值 |
| 读取失败或值不是有限数 | 无有效来源 | 提示读取失败或数值无效，不查表回传 |

- 两个地址独立，均为 Siemens REAL，直接传输数值，例如 2.5，无倍率换算。
- 不提供需要流水线操作员逐台切换的扭矩来源开关。
- 非零读取值持续有效；软件不判定其是否来自上一台，不要求 PLC 每台清零，不根据 SN 变化使其失效。
- 0 是读取地址上选择软件表的约定值；正零和负零都按 0 处理。不使用近零阈值。
- 非零负值也遵守非零优先规则，不擅自改变符号或取绝对值。
- 读取失败、未匹配、无效数值、回传失败均不阻止已触发的声学测试，不改变声音分析或 PASS/FAIL。
- SN、型号显示区域增加扭矩行；软件扭矩表支持 Excel 导入。

## 方案选择

采用“Excel 导入本地持久化表，测试时查询内存快照”的方案：客户批量维护方便，运行不依赖 Excel 文件仍在原路径，导入校验与 PLC 通信相互独立。

另一种方案是每次测试直接读取 Excel 文件，可即时使用文件中的修改，但会把文件占用、移动、格式错误和读取延迟带入生产测试。前述本地表方案作为本次设计。

## 范围与兼容边界

功能绑定现有普通测试 PLC；同一台 PLC 使用已有连接，读取和回传地址分别配置 DB 与偏移。扭矩值只用于本次显示与指定地址回传，不增加声学判定条件。

保留工艺 PLC、既有工单读取、启动信号复位、录音时间戳、测试结果回传和电流采集行为。手动测试及音频导入不触发本功能。扭矩不加入现有声音结果回传批次，也不触发结束位。

本次交付包括扭矩配置与表管理、Excel 模板与导入、PLC 运行链路、工单区域显示、兼容迁移及验证。扭矩历史报表、远程同步、既有配置包格式扩展不在本次范围。

## PLC 扭矩配置

在硬件页现有 PLC 管理区域提供该 PLC 的“扭矩配置”入口，包含：

- 启用扭矩功能：默认关闭。
- 查表依据：型号 / SN；默认型号。只查询选中的类型，无 SN 优先或跨类型回退。
- 扭矩读取地址：DB 块号、字节偏移。
- 扭矩回传地址：DB 块号、字节偏移。
- 固定类型 REAL，仅作说明，不提供整数类型或倍率设置。
- “管理扭矩表”入口，打开全软件共享的扭矩表。

DB 留空表示沿用该 PLC 工作线程当前已应用的 DB，不读取界面上尚未应用的基础 DB 值。偏移接受非负整数字节地址，也接受现有 N.0 形式并规范化为字节地址；位部分不为 0 时拒绝保存。两个地址各占 4 字节，同一 DB 中不能重叠。启用时两个地址必须完整有效；关闭时允许尚未配置地址。基础 DB 的生效沿用现有连接配置流程；应用或重连时须按实际 DB 重新检查两个地址，冲突时仅停用该次扭矩处理并显示配置错误，测试继续。

保存配置不向 PLC 写入扭矩。配置变化在 PLC 工作线程完成更新后对之后的开始事件生效；已经开始的处理使用开始时固定的配置快照。界面保存成功表示配置已持久化，另行显示运行配置已应用或待应用，避免断开的 PLC 阻塞配置保存。删除 PLC 时删除其扭矩配置，共享扭矩表保留。

## 扭矩表与匹配

全软件维护一张本地表，记录字段为：匹配类型（型号或 SN）、匹配值、扭矩。唯一键为“匹配类型 + 匹配值”。每台 PLC 根据自己的查表依据查询同一表。

匹配值只去掉首尾空白，保持大小写、内部字符和前导零；读取的型号 / SN 使用同一规则。使用完整字符串精确匹配，不解析 SN 内嵌型号，不使用正则或模糊匹配。

扭矩接受能编码为有限 REAL 的数值，包括零和负数；拒绝 NaN、Infinity、布尔值、溢出或非零数编码后下溢成零的值。PLC 读取地址的零是来源选择信号，软件表中的零则是可直接回传的实际值。Excel、编辑界面和回传共用同一数值校验。

管理窗口提供新增、编辑、删除、搜索、Excel 导入和下载模板。保存后原子更新持久化记录并发布只读规则快照；运行链路使用快照，不读取 Excel，也不在 PLC 线程执行数据库查询。当前处理固定使用开始时的版本，之后的开始事件使用新版本。

单位沿用现场双方使用的单位，软件不进行换算，也不根据猜测给数值附加单位；界面和模板注明“与 PLC 单位一致”。

## Excel 导入

支持 .xlsx，使用仓库现有 openpyxl 依赖；不支持旧 .xls、宏或公式求值。提供单工作表模板，首行为以下表头：

| 匹配类型 | 型号或SN | 扭矩 |
| --- | --- | --- |
| 型号 | M100 | 2.5 |
| SN | SN000123 | 2.6 |

- 读取第一个工作表；表头去首尾空白后须符合模板，可调整列顺序。
- “匹配类型”只接受“型号”或“SN”。型号或 SN 必须为文本，模板将该列设置为文本格式，以保留前导零和长 SN；数值型匹配键报错，不猜测其原始文本。
- 扭矩接受 Excel 数值或可转换为数值的文本，并通过统一 REAL 校验；公式单元格报错，不读取缓存计算值。
- 完全空行跳过；其余缺值、非法类型、无效扭矩及同一文件内重复唯一键均报错，并列出 Excel 行号及原因。
- 导入预览显示新增、覆盖和错误记录，以及覆盖项的新旧值。有错误时不能提交任何行；取消预览不修改数据。
- 用户确认后按唯一键新增或覆盖；本次文件未包含的已有记录保留。所有记录在单一事务中提交，失败整批回滚。
- 预览和提交之间表版本变化时要求重新生成预览，避免覆盖用户没有看过的改动。
- 文件解析在后台执行，预览与提交期间不阻塞现有测试。仅提交成功后发布新规则快照。

## 运行流程与线程边界

当前代码入口是 app/service/plc_service.py 的 PlcService.poll_once()。它在开始位上升沿记录时间、读取 SN / 型号 / 转速，并调用 _on_start_requested。ui/modules/workorder.py 按 plc_id 展示工单。现有 PLC 读写使用所属 Qt 工作线程与 Snap7 客户端。

新增逻辑保持以下顺序与边界：

1. 复用已有开始位判定和工单读取，固定本次 plc_id、触发标识、型号 / SN，以及扭矩配置与规则快照。
2. 按原有接口提交开始测试事件、处理原有开始位复位。扭矩读取或写入不得前置到开始事件提交之前，也不得改变原触发时间戳。
3. 原有开始回调未抛出异常且扭矩功能启用时，在该 PLC 所属线程执行一次扭矩处理。沿用现有开始事件提交语义，不新增声学系统接受回执或启动握手。开始位复位尝试失败需独立记录，不因此跳过扭矩处理，也不新增复位重试；若连接已不可用，则扭矩处理直接报告读取失败。
4. 直接读取扭矩地址的 4 个字节，独立校验结果；不可用把读错误吞掉后返回默认 0 的工单读取接口。
5. 非零有限值：发布 PLC 来源的显示状态，不查表，不写任一扭矩地址。
6. 零值：按快照查表；找不到时发布未匹配。找到后发布待回传值，在回传地址写入 REAL；调用成功后显示已回传，失败则显示回传失败。
7. 每个开始事件最多一次读取、一次表值回传；开始位保持高电平时不重复处理。不因导入、改表、页面刷新、重连或结果完成重放旧扭矩请求。

扭矩异常在该处理边界转成状态与日志，不能跳过已约定的开始提交和复位，不能抛入声学分析链路。网络访问保持已有有限超时；UI 线程、录音线程不等待扭矩网络操作。扭矩处理可能占用所属 PLC 通信线程的一个有限读写周期，不承诺 PLC 电流轮询在通信失败期间完全无延迟。

不另建 Snap7 连接，不从导入线程或 UI 直接访问客户端，不修改公共 _db_number 来访问不同 DB；向扭矩专用读写接口显式传递 DB 和字节地址。

“已回传”只表示本次 Snap7 写操作成功，不表示 PLC 已执行负载，也不额外读取验证或引入握手。

## 显示与日志

每个 PLC 的型号下增加只读“扭矩”行，复用当前工单面板布局，适配多 PLC 和滚动区域：

| 状态 | 显示示例 |
| --- | --- |
| 未启用 | 未启用 |
| 已启用但尚无开始事件 | 待读取 |
| 开始处理 | 读取中 |
| PLC 输入 | 2.5（PLC） |
| 软件表待写 | 2.5（软件表，回传中） |
| 软件表写入成功 | 2.5（软件表，已回传） |
| 表中无记录或本次匹配键为空 | 未匹配（型号：M100） / 未匹配（型号为空） |
| 读取失败 | 读取失败 |
| 实际 DB 下地址配置无效 | 扭矩配置错误 |
| 非有限 PLC 数值 | PLC 扭矩无效 |
| 表中值已找到但写入失败 | 2.5（软件表，回传失败） |

显示本次已知的值和状态，不把失败改成 0，也不把上一显示值当作本次成功结果。使用 plc_id 与触发标识关联异步显示更新，避免界面更新串到别的 PLC 或较新的事件；这是 UI 事件关联，不参与 PLC 值是否有效的业务判断。

日志记录 PLC、触发标识、型号 / SN、规则版本、读取值、最终来源、目标地址、回传值及错误原因。生产时采用状态行和日志，不弹出需要操作员逐台关闭的模态错误框。

## 数据存储与兼容迁移

新增两个专用表：

- plc_torque_config_table：plc_id 主键、enabled（默认 false）、match_type（默认 model）、read_db_number / read_byte_offset、write_db_number / write_byte_offset。DB 可空表示继承，偏移在关闭功能时可空。
- torque_rule_table：记录 ID、match_type、match_key、torque_value，以及唯一索引 (match_type, match_key)。扭矩按可回传的 REAL 数值保存；版本用于进程内快照与导入预览一致性。

避免把扭矩加入现有结果字段集合或配置限值回传集合。扭矩设置与共享表独立持久化，既有 .dy 测试配置包维持原格式。

在现有 DbConnectionService 的兼容升级流程中为已存在、通过原有基础校验的数据库添加这两个表和索引，升级前沿用 SQLite 备份机制。升级可重复执行、事务化，保留现有数据及已完成的兼容迁移。数据库首次缺少文件或原有必需表时仍按现有策略报错，不创建替代空生产数据库。迁移新表之后再校验其结构；无配置记录等价于关闭功能。

开发验证仅使用临时数据库；交付包含迁移逻辑，不在开发时改写用户实际 data/jingchen.db。

## Compatibility / Migration

- Backward compatibility: required
- Protected surfaces: [旧数据库业务记录、原有 PLC 连接和字段偏移、测试启动与开始位复位语义、录音触发时间戳、工单 SN 和型号、声学分析及结果、工艺 PLC、PLC 电流采集、现有 .dy 配置包、手动测试和导入音频行为]
- Allowed breakage: []
- Migration strategy: other — 在既有备份与兼容升级机制中事务化新增专用表及索引；缺省关闭；不重建或批量改写原有业务数据。

## 验收与验证

1. PLC 读取 0，型号 M100 命中 2.5：原开始事件先提交，指定回传 DB / 偏移收到可解码为 2.5 的 4 字节 REAL，显示软件表及已回传。
2. PLC 读取 3.0，表中为 2.5 或完全无记录：显示 PLC 3.0，无扭矩写入；后续多次开始读取仍为 3.0 时继续采用它，不要求数值变化。
3. PLC 读取正零、负零时查表；微小非零值和负非零值保留 PLC 优先语义；无效数值不被转成表回退条件。
4. 按型号和 SN 分别精确匹配；验证前导零、大小写、空键、同值不同类型、多 PLC 隔离。
5. 读取断线、短数据、非有限数值、表未命中及回传异常均不改变开始事件、复位或声学结果；状态准确且不显示旧成功结果。开始事件提交成功但开始位复位失败时，保留原复位尝试及其错误日志，并得到本次扭矩处理状态。
6. 开始位持续高、首次采样高、重连、保存配置、表导入及结果完成均不额外写入；功能关闭时零新增扭矩网络请求。
7. Excel 正常导入、模板文本列、行号报错、公式、重复键、无效 REAL、取消、覆盖预览、事务失败回滚及预览版本冲突。
8. 活跃测试期间导入 / 修改只影响之后的处理，当前处理使用同一版本；配置在所属 PLC 线程应用，无跨线程 Snap7 调用。继承 DB 与工作线程已应用值一致，重连后的地址冲突显示配置错误且不执行扭矩读写。
9. 临时旧数据库升级、幂等升级、升级失败回滚及备份、旧记录与 .dy 格式保持；缺少原有生产数据库时仍遵循现有启动失败行为。
10. 工单界面覆盖两台以内和多台 PLC 的新增行与滚动，状态消息按 PLC 和触发事件正确关联。

验证使用假 PLC 与临时 xlsx / SQLite 文件，运行相关 PLC 启动和调度、工单界面及数据库兼容回归。实机地址和通信效果留待部署后的现场联调，开发测试不得自动连接真实 PLC。
