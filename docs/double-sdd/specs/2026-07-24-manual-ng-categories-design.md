# 手动 NG 类别设计

日期：2026-07-24

## 背景与问题

当前工厂测试流程支持自动判定，以及操作员通过“手工合格”和“手工不合格”覆写当前测试记录的最终判定。手工判定会更新同一条音频测试记录，并沿用现有页面清理和下一件准备流程。

现有“手工不合格”只能记录通用的 `NG`，无法说明具体不合格类别。不同测试配置需要维护各自的手动 NG 类别列表；当当前测试配置设置了类别时，操作员点击“手工不合格”必须先从该列表中选择一项。

## 已有行为

- 自动分析完成后会把自动判定写入当前测试的音频数据记录。
- 操作员不点击手工按钮时，自动判定就是该记录的最终判定。
- 手工 OK/NG 可覆写同一条记录的 `labels` 和 `label_source`。
- 手工判定成功后，控制器通过既有 `manual_judgment_ok` 或 `manual_judgment_ng` 重置原因清理本件显示并准备下一件。
- 当前配置由 `TestConfigTable`、`ConfigService` 和 `ConfigModule` 管理。
- 配置包服务负责配置的导入和导出。
- `AudioDataTable` 保存最终标签、判定来源和配置快照；数据管理页按模型字段展示和导出记录。

## 目标

1. 每条测试配置可以维护一个有序的手动 NG 类别名称列表。
2. 当前配置存在类别时，点击“手工不合格”必须选择类别后才能提交。
3. 当前配置没有类别时，保持现有手工 NG 行为。
4. 把选中的类别保存到当前测试的同一条音频数据记录。
5. 在数据管理表格和导出数据中展示手动 NG 类别。
6. 不改变未使用手工按钮时的自动判定流程。
7. 不改变手工 OK，以及手工 NG 选择完成后的现有判定覆写、页面重置和下一件准备行为。
8. 保持 PLC、MES 或其他外部接口的原有 OK/NG 协议。

## 非目标

- 不增加自动判定类别。
- 不根据自动分析指标自动选择手动 NG 类别。
- 不为类别增加编码、说明、颜色或其他属性。
- 不增加类别筛选、类别统计或类别报表。
- 不向 PLC、MES 或其他外部系统传输类别。
- 不增加人工确认等待状态、倒计时或自动选择类别。
- 不保存手工判定修改历史。
- 不为旧数据库或旧配置包提供迁移或兼容支持。

## 判定优先级与流程不变约束

### 未点击手工按钮

- 自动分析完成后，继续按现有流程立即保存自动判定。
- 不弹出类别窗口。
- 不进入等待人工确认状态。
- 不阻塞或延迟现有页面和下一次测试流程。
- 自动记录保持：
  - `labels` 为自动分析得到的 `OK` 或 `NG`；
  - `label_source = "auto"`；
  - `manual_ng_category = NULL`。

### 点击“手工合格”

- 行为保持不变，不弹出类别窗口。
- 成功时更新同一条测试记录：
  - `labels = "OK"`；
  - `label_source = "manual"`；
  - `manual_ng_category = NULL`。
- 成功后的页面重置、SN 清理、视频保留和下一件准备行为继续使用现有手工 OK 流程。

### 点击“手工不合格”

- 当前测试配置的类别列表为空时：
  - 不弹出类别窗口；
  - 直接执行现有手工 NG 动作；
  - 成功时保存 `manual_ng_category = NULL`。
- 当前测试配置存在类别时：
  - 先弹出类别单选窗口；
  - 操作员必须主动选择一个类别并确认；
  - 确认后执行现有手工 NG 动作，并额外保存所选类别；
  - 选择完成后的记录覆写、页面清理和下一件准备行为不得改变。
- 成功时更新同一条测试记录：
  - `labels = "NG"`；
  - `label_source = "manual"`；
  - `manual_ng_category` 为本次选择的类别名称，或在无配置类别时为 `NULL`。

## 配置界面

### 顶层配置卡片

在配置页新增顶层卡片“手动 NG 类别”，与现有结果展示布局、硬件、AI 等顶层配置卡片采用相同的打开和确认模式。

卡片内容使用有序列表，不使用多列表格。提供以下操作：

- 新增；
- 重命名；
- 删除；
- 上移；
- 下移。

列表展示顺序就是手工 NG 选择窗口的展示顺序。

### 编辑规则

- 每项只包含类别名称。
- 新增或重命名时去除名称首尾空格。
- 去除首尾空格后为空的名称无效。
- 同一配置内不允许存在完全相同的类别名称。
- 重复比较使用去除首尾空格后的完整名称；不额外执行大小写折叠、Unicode 改写或近似匹配。
- 类别名称不得包含换行、制表符或其他 Unicode 控制字符；不另设产品层面的字符数上限。
- 列表为空是合法配置。
- 删除和排序操作立即反映在编辑器本地状态中，但只有保存配置后才成为持久化配置。
- 类别列表必须纳入配置页现有的未保存更改检测、保存失败恢复、切换配置确认和编辑器快照逻辑。
- 新建配置时类别列表为空。
- 加载或切换配置时必须显示对应配置自己的类别列表，不得保留上一配置的类别。

`ConfigService` 是最终校验边界。即使 UI 已校验，服务层仍必须拒绝非列表、非字符串、空名称和重复名称。

## 手工 NG 类别选择窗口

### 打开条件

操作员点击“手工不合格”时，系统先捕获当前展示/复核运行的不可变身份：

- `config_id`
- `run_id`

系统根据该 `config_id` 读取已保存测试配置的类别列表，并对规范化后的完整有序列表计算版本指纹。指纹采用规范 JSON（UTF-8、保持列表顺序）内容的 SHA-256 值。系统把 `config_id`、`run_id`、完整有序列表及其指纹作为本次选择上下文；弹窗不得在提交时悄悄改用新的当前运行。

- 无类别：不打开窗口，直接调用现有手工 NG 流程。
- 有类别：打开单选窗口。
- 无法解析当前展示运行的配置，或配置读取失败：显示可见警告，不提交手工判定，不改变当前页面。

不得从配置页尚未保存的编辑器状态读取类别。

### 窗口行为

- 标题和内容明确说明正在选择“手动 NG 类别”。
- 按配置列表顺序展示类别。
- 初始不预选任何项。
- 未选择类别时，“确认”不可提交。
- 选择一项并确认后才请求手工 NG。
- 取消或关闭窗口等同于没有点击手工按钮：
  - 不写数据库；
  - 不改变判定；
  - 不发出页面重置信号；
  - 不清理 SN 或显示内容；
  - 不改变工厂控制器状态。

### 提交时的再次校验

UI 选择不是可信数据边界。手工 NG 提交必须携带打开时捕获的 `config_id`、`run_id` 和列表指纹。控制器/服务必须验证：

- 当前展示/复核运行的 `config_id + run_id` 仍与捕获身份一致；
- 目标会话仍精确属于捕获的 `config_id + run_id`；
- 当前持久化配置仍存在；
- 重新读取并规范化后的完整有序列表指纹与捕获指纹一致；
- 当前类别列表非空时，提交值必须精确匹配其中一项；
- 当前类别列表为空时，只允许空类别；
- 类别只允许与 `NG` 一起提交；
- `OK` 请求不得携带类别。

任何重命名、删除、增加或重排都会改变列表指纹，即使原选择名称仍存在，也必须拒绝旧选择。如果弹窗打开后展示运行变化、配置被删除或列表指纹变化，系统应拒绝请求、显示可见提示并保持当前页面不变。操作员可重新点击按钮并使用最新运行与列表。

`config_id + run_id` 保护测试记录归属，完整列表指纹保护选择上下文，两者均不得只靠类别名称匹配替代。

## 类别配置时点

手动 NG 类别以操作员点击按钮时该运行关联配置的最新持久化列表为准，不使用配置页未保存内容，也不强制使用运行开始时的配置快照。

因此，运行开始后、点击按钮前已保存的类别变化可用于本次选择；音频记录的 `config_content` 仍表示原有运行配置快照，不因手工判定而改写。`manual_ng_category` 是历史记录中本次实际人工选择的权威值。按钮点击后发生的任何列表变化则通过指纹使本次选择失效。

## 数据模型

### 测试配置

在 `TestConfigTable` 新增：

- ORM 字段：`manual_ng_categories`
- DB 列：`manual_ng_categories`
- 类型：文本，非空
- 默认值：`"[]"`
- 内容：JSON 字符串数组，按 UI 顺序保存规范化后的类别名称

`ConfigService.load_config()` 对外返回：

```text
manual_ng_categories: list[str]
```

`ConfigService` 保存配置时把规范化列表序列化为 JSON。配置快照也必须包含该字段，使测试运行的配置内容完整可追溯。

### 音频测试记录

在 `AudioDataTable` 新增：

- ORM 字段：`manual_ng_category`
- DB 列：`manual_ng_category`
- 类型：可空文本
- 默认值：`NULL`

该字段保存操作员实际选择的类别名称，而不是列表索引。配置列表以后被改名、删除或重排时，不得改变历史测试记录的含义。

字段语义：

- 自动 OK/NG：`NULL`
- 手工 OK：`NULL`
- 无配置类别时的手工 NG：`NULL`
- 有配置类别时的手工 NG：所选类别名称

## 持久化与原子性

手工判定继续更新捕获的 `config_id + run_id` 所精确对应的现有音频数据记录，不创建第二条记录。

手工 NG 的以下字段必须由同一次数据库更新完成：

- `labels = "NG"`
- `label_source = "manual"`
- `manual_ng_category = <所选名称或 NULL>`

手工 OK 的以下字段必须由同一次数据库更新完成：

- `labels = "OK"`
- `label_source = "manual"`
- `manual_ng_category = NULL`

自动判定持久化必须明确写入 `manual_ng_category = NULL`，避免同一记录再次判定时留下过期类别。

提交后端必须在同一个 SQLite 事务中：

1. 读取捕获 `config_id` 对应的当前配置行；
2. 解析、规范化并校验完整类别列表；
3. 比较完整列表指纹；
4. 由捕获的 `config_id + run_id` 解析目标会话和音频数据行；
5. 原子更新最终标签、来源和类别。

控制器在进入事务前验证当前展示身份仍等于捕获身份；`TestManager` 不使用“当前会话”捷径，而是按捕获身份解析目标。配置读取、指纹验证和音频行更新共享同一数据库事务，从而避免验证后配置又被修改的检查—使用竞态。若身份或指纹验证失败，事务不更新任何记录。

如果数据库更新失败：

- 三个字段不得出现部分更新；
- 不执行页面重置；
- 当前显示和 SN 保持不变；
- 向操作员显示现有风格的可见错误提示。

## 组件职责

### `ConfigModule`

- 创建并管理“手动 NG 类别”顶层卡片。
- 维护有序列表的新增、重命名、删除和移动交互。
- 将列表纳入 `_collect_data()`、`_populate_detail()` 和未保存更改快照。
- 提供即时的空名称和重复名称反馈，但不代替服务层校验。

### `ConfigService`

- 在配置加载字段、返回数据和保存数据中加入 `manual_ng_categories`。
- 负责规范化、服务层校验、JSON 序列化和解析。
- 确保配置快照包含列表。

### 配置包服务

- 把 `FORMAT_VERSION` 从 `1` 提升为 `2`。
- 所有新导出包的 `manifest.json.format_version` 必须为 `2`。
- 版本 2 的 `config/config.json` 必须包含 `config.manual_ng_categories`。
- 版本 2 导入必须恢复类别列表并经过与普通保存相同的服务层校验。
- `format_version = 1`、其他版本、缺少 `manual_ng_categories` 或该字段无效的包必须在任何数据库或文件系统变更前确定性拒绝。
- 不为版本 1 或缺少该字段的配置包提供默认值或兼容分支。

### `ControlModule`

- 保持手工 OK 按钮接线不变。
- 手工 NG 点击时向控制器取得当前持久化类别。
- 无类别时直接发起原手工 NG 请求。
- 有类别时显示单选窗口，并仅在确认有效选择后提交。
- 显示配置读取、选择失效或手工判定失败的可见提示。
- 不直接访问或更新音频数据表。

### `FactoryModeController`

- 根据当前展示/复核运行确定其测试配置。
- 在点击时捕获并提供 `config_id + run_id`、当前持久化手动 NG 类别及完整列表指纹。
- 保留现有忙碌状态、运行归属和可手工判定资格校验。
- 在提交时拒绝展示身份变化，并把捕获身份、指纹和选择传给后端重新校验。
- 后端更新成功后，继续调用现有 `clear_for_next_run("manual_judgment_ng")`。
- 失败或取消时不清理页面。

### `TestManager`

- 扩展手工判定调用，使 NG 可携带可空类别。
- 保持现有会话查找、运行归属和忙碌状态保护。
- 只按捕获的 `config_id + run_id` 解析目标会话，不在提交时改用新的“当前会话”。
- 在共享数据库事务中重新读取配置、比较完整列表指纹并更新目标音频行。
- 仍拒绝 OK 携带类别等结构性无效请求。

### `TestSession`

- 在当前音频数据行上原子更新最终标签、判定来源和类别。
- 手工 OK 和自动判定明确清空类别。
- 保持“一次测试一条音频记录”的约束。

### `AudioDataService` 与数据管理页

- 把 `manual_ng_category` 作为普通记录字段读取和导出。
- 数据管理表头显示为“手动NG类别”。
- `NULL` 或空值显示为空白。
- 不增加类别筛选控件。

### PLC 与外部接口

- 不增加字段、寄存器、信号或消息。
- 自动判定和手工判定仍只按现有协议输出 OK/NG。
- 手动 NG 类别不得改变现有 PLC 复位或结果输出时序。

## 错误处理

以下情况必须提供可见反馈，并且不更新记录、不清理页面：

- 当前展示运行无法关联到测试配置；
- 配置读取失败；
- 当前展示运行的 `config_id` 或 `run_id` 与弹窗打开时不同；
- 目标会话不属于捕获的 `config_id + run_id`；
- 类别列表数据损坏；
- 完整类别列表的内容或顺序发生变化；
- 有配置类别但未提交类别；
- 提交类别不在最新持久化列表中；
- 空列表配置却提交了非空类别；
- OK 请求携带类别；
- 现有手工判定资格校验失败；
- 当前音频数据行不存在；
- 数据库更新失败。

配置编辑中的无效类别必须阻止配置保存，并指明空名称或重复名称问题。

## Compatibility / Migration

- Backward compatibility: not required
- Protected surfaces: [new database schema, configuration package format version 2, unchanged automatic-judgment behavior, unchanged manual-judgment reset behavior, factory-mode one-test-one-record behavior, existing PLC OK/NG protocol, user-visible data-management behavior]
- Allowed breakage: [databases without `test_config_table.manual_ng_categories`, databases without `audio_data_table.manual_ng_category`, configuration package format version 1, configuration packages missing `manual_ng_categories`]
- Migration strategy: none

本功能不增加运行时加列、迁移脚本、旧包默认值或兼容层。

## 预置数据库与启动门禁

运行数据库是部署时放置在 `<base_dir>/data/jingchen.db` 的外部预置产物；它不由 PyInstaller 打包，也不由应用首次启动创建。实现交付时必须在开发、测试和发布交接所使用的权威预置数据库中预先创建：

- `test_config_table.manual_ng_categories TEXT NOT NULL DEFAULT '[]'`
- `audio_data_table.manual_ng_category TEXT NULL`

该预置数据库仍按项目现有发布流程复制到可执行程序旁的 `data/jingchen.db`，不把运行时迁移引入应用。

`DbConnectionService` 的启动架构门禁必须扩展：

- 把 `manual_ng_categories` 加入必需的 `test_config_table` 列；
- 新增必需的 `audio_data_table` 列集合，并要求 `manual_ng_category`；
- 任一列缺失时，在服务创建和业务读写之前抛出 `DatabaseStartupError`，关闭连接，并提示复制完整预置数据库；
- 两列都存在时正常启动。

内存数据库测试可继续使用测试夹具建表；非内存启动门禁测试必须使用临时预置数据库文件验证真实 `PRAGMA table_info` 行为。

## 测试要求

### 配置模型与服务

1. 新配置的类别列表默认为空。
2. 有序类别列表保存后可原顺序加载。
3. 名称首尾空格被去除。
4. 非列表、非字符串、空名称、控制字符和重复名称被拒绝。
5. 配置快照包含规范化后的类别列表。

### 配置界面

1. 支持新增、重命名、删除、上移和下移。
2. 切换配置不会串用列表。
3. 新建配置显示空列表。
4. 列表修改会触发未保存更改检测。
5. 放弃修改和保存失败恢复到权威持久化列表。

### 配置包

1. 新格式导出包含类别列表。
2. 导出清单的 `format_version` 为 `2`。
3. 版本 2 导入恢复列表顺序和内容。
4. 导入数据仍执行空名称、控制字符和重复名称校验。
5. 版本 1、未知版本、版本 2 缺少字段及字段无效的包均在任何持久化副作用前确定性拒绝。

### 手工判定交互

1. 无类别时点击手工 NG 不弹窗，并保持现有成功流程。
2. 有类别时显示按配置顺序排列的单选窗口。
3. 初始无选择，未选择不能提交。
4. 取消或关闭窗口不调用手工判定，也不产生状态或页面副作用。
5. 选择有效类别后调用现有手工 NG 流程。
6. 弹窗期间 `run_id` 变化时，旧选择被拒绝，记录和页面不变，并显示反馈。
7. 弹窗期间展示 `config_id` 变化时，旧选择被拒绝，记录和页面不变，并显示反馈。
8. 配置被删除时显示反馈且不提交。
9. 持久化 JSON 损坏时显示反馈且不提交。
10. 列表重命名、删除、增加无关项或重排时，即使原选择仍存在，指纹变化也会拒绝提交。
11. 上述失败均不更新记录、不清理页面并显示反馈。
12. 手工 OK 不弹出类别窗口。

### 持久化

1. 自动 OK/NG 写入 `manual_ng_category = NULL`。
2. 手工 OK 写入 `labels = "OK"`、`label_source = "manual"` 和空类别。
3. 无配置类别的手工 NG 写入 `labels = "NG"`、`label_source = "manual"` 和空类别。
4. 有配置类别的手工 NG 把所选名称写入同一条音频记录。
5. 不允许 OK 携带类别。
6. 非法或过期类别不能更新任何判定字段。
7. 数据库错误不能造成标签、来源和类别的部分更新。
8. 手工覆写不创建第二条音频数据记录。

### 数据库交付与启动

1. 缺少 `test_config_table.manual_ng_categories` 的文件数据库启动失败。
2. 缺少 `audio_data_table.manual_ng_category` 的文件数据库启动失败。
3. 两列完整的预置文件数据库启动成功。
4. 启动门禁只检查并拒绝不完整架构，不自动新增列。
5. 发布交接的预置 `data/jingchen.db` 通过完整启动门禁。

### 流程回归

1. 不点击手工按钮时，自动判断和当前流程完全不变。
2. 手工 OK 的成功、失败和页面重置行为保持不变。
3. 手工 NG 在选择确认后的成功、失败、页面重置、SN 清理、视频保留和下一件准备行为保持不变。
4. 手工 NG 取消选择时不触发页面重置。
5. PLC 仍只接收现有 OK/NG，结果输出和复位时序不变。

### 数据管理

1. 表头显示“手动NG类别”。
2. 类别名称按原文本显示。
3. `NULL` 显示为空白。
4. 导出记录包含 `manual_ng_category`。
5. 现有 OK/NG 和判定来源筛选、统计及导出行为不受影响。

## 完成标准

- 配置可可靠维护每个测试配置独立的有序类别列表。
- 无类别时手工 NG 与当前版本行为一致。
- 有类别时必须选择有效类别才能执行同一套手工 NG 后续流程。
- 不使用手工按钮时，自动判定行为与当前版本一致。
- 选中类别与最终 NG 判定一起可靠保存到同一条测试记录。
- 数据管理和导出能看到该类别。
- 手工 OK、PLC 协议及现有页面重置行为没有变化。
- 所有目标测试与相关回归测试通过。
