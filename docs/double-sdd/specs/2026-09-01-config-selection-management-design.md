# 配置选择迁移到配置管理设计规格

## 背景

当前“测试”主页的“工单”卡片内嵌“配置选择”列表。工程师或管理员可以勾选多个测试配置、拖拽调整顺序，并以第一项作为首选配置。该选择同时参与启动就绪校验、工单发布、PLC 启动信号复位、持久化、配置失效修剪和运行阶段锁定。

配置选择属于生产配置管理职责，不属于操作员的日常主页操作。主页应释放这块长期占用的空间，并避免操作员误改生产使用的配置。

## 目标

- 从“测试”主页移除可操作的配置选择区域。
- 在“配置”页提供“选择使用配置”按钮。
- 点击按钮后以模态弹窗完成多配置勾选和首选顺序调整。
- 只有拥有“配置”页权限的管理员和工程师可以修改选择；操作员只能使用已保存的选择。
- 保留现有选择对启动、PLC、工单、持久化和配置变更的联动语义。

## 非目标

- 不改变配置的新建、编辑、删除、导入或导出功能。
- 不改变角色权限模型；继续使用现有顶部页签权限控制。
- 不改变配置选择的持久化格式、数据库结构或配置包格式。
- 不重构测试执行、PLC 路由或结果展示流程。
- 不允许在弹窗中创建或编辑配置；弹窗只负责选择和排序。

## 用户体验设计

### 测试主页

- “工单”卡片不再显示“配置选择”标题、选择列表或选择持久化提示。
- PLC SN、产品型号以及当前运行阶段等现有工单信息继续显示。
- 启动按钮附近现有的阻塞原因仍负责提示“请至少启用一个配置”、配置失效或配置校验失败等问题。
- 工单发布的 `selected_config_ids` 继续来自工厂模式的权威状态，而不是主页控件。

### 配置管理入口

- 在“配置”页左侧配置列表的操作区增加“选择使用配置”按钮。
- 按钮是独立于当前单条配置编辑状态的全局操作：打开弹窗不保存、丢弃或切换当前正在编辑的配置。
- 没有任何配置时按钮仍然可点击。弹窗显示空列表和“配置列表为空，请先新建配置。”，并禁用“确定”；用户可取消或关闭弹窗返回配置管理页。

### 配置选择弹窗

- 标题为“配置选择”。
- 复用现有 `FactoryConfigListWidget` 的视觉和行为：
  - 勾选一个或多个配置；
  - 已勾选配置排在未勾选配置之前；
  - 拖拽已勾选配置改变优先顺序；
  - 第一项显示“首选”标记。
- 弹窗显示简短说明：“勾选生产使用的配置，拖拽可调整优先顺序，第一项为首选配置。”
- 弹窗提供“确定”和“取消”：
  - 打开时以权威工厂状态建立草稿快照；
  - 勾选和拖拽只修改弹窗草稿；
  - “取消”、关闭窗口或按 Escape 均丢弃草稿；
  - “确定”时至少需要一个已勾选配置；为空时显示校验提示并保持弹窗打开；
  - 成功确认后才更新工厂状态、发布工单并持久化。
- 运行阶段为 `running`、`analyzing`、`reanalyzing`，或启动请求正在处理时，弹窗允许查看当前选择，但选择框和拖拽排序不可用，“确定”不可提交变更，并显示锁定原因。
- 配置列表在弹窗每次打开时重新读取，避免使用已删除、已导入或已重命名的陈旧数据。

## 权限行为

- 管理员和工程师拥有“配置”页权限，因此可以看到并使用“选择使用配置”按钮。
- 操作员没有“配置”页权限，主页也不再提供配置选择入口，因此不能修改配置选择。
- 操作员启动测试时继续使用管理员或工程师最后成功保存的选择。
- 本改动不新增单独的按钮级权限判断；权限边界由现有页签权限保证，测试需验证操作员无法通过主页控件访问该功能。

## 组件与职责

### `FactoryModeController`

- 继续作为权威 `selected_config_ids` 和运行阶段的状态所有者。
- 承接目前散落在 `WorkOrderModule` 中、但并非主页展示职责的选择编排：
  - 加载并修剪启动时的持久化选择；
  - 去重并恢复选择状态；
  - 对新增配置请求 PLC 启动信号复位；
  - 应用确认后的选择；
  - 按现有规则持久化选择并发出失败或重启提示。
- 提供一个返回结构化结果的确认入口，结果至少区分 `applied`、`restart_required`、`unchanged` 和 `rejected`，并携带可显示消息及最终权威选择。
- 配置变更后的选择刷新和失效配置修剪继续沿用现有逻辑。

### `WorkOrderModule`

- 只负责显示工单/PLC 信息、发布工单载荷和反映工厂运行状态。
- 不再创建或持有 `FactoryConfigListWidget`。
- `value()` 从 `FactoryModeController.state.selected_config_ids` 读取选择。
- 收到 `factory_state_changed` 后刷新内部权威状态并在选择变化时发布新的工单载荷。
- 不再加载、修剪、恢复或持久化配置选择，也不再请求选择相关的 PLC 复位。

### 配置选择弹窗

- 新增专用弹窗组件，持有 `FactoryConfigListWidget` 和确定/取消按钮。
- 负责加载可选配置、维护草稿、校验非空、展示锁定与持久化提示。
- 确认时调用工厂模式控制器公开的选择应用入口，不直接修改数据库或复制业务校验。
- 监听 `factory_state_changed` 和 `config_changed`，保证弹窗打开期间的锁定状态和配置列表保持一致。
- 打开时记录权威选择基线。若仅运行阶段变化，则保留草稿并更新只读状态；若外部事件改变了 `selected_config_ids`，则丢弃当前草稿、以最新权威选择重建列表，并显示“配置选择已更新，请重新确认。”，防止旧草稿覆盖新状态。
- 若 `config_changed` 使草稿包含失效 ID，则从草稿中修剪这些 ID、保留其余顺序并显示“部分配置已失效，请重新确认。”；若随后收到权威选择变化，以权威状态重建规则为准。

### `ConfigModule`

- 创建“选择使用配置”按钮并负责打开单例模态弹窗。
- 不把运行配置选择并入当前单条配置的脏状态、保存按钮或离开确认流程。
- 配置列表刷新后不隐式改变已确认的使用配置；由现有工厂模式配置变更处理负责修剪失效项。

## 数据与事件流

### 应用启动

1. `ServicesContainer` 是唯一的启动选择初始化调用方；它在构建主页之前调用工厂模式控制器的幂等初始化入口一次。
2. 初始化入口从 `FactorySelectionSettings` 读取已保存或待重启生效的配置 ID 顺序。
3. 根据当前配置列表修剪失效 ID 并去重，并按现有启动对账规则提交为权威持久化选择。
4. 工厂模式控制器恢复权威运行选择状态，并对恢复后的配置执行现有 PLC 启动信号复位请求。
5. `WorkOrderModule` 只读取已初始化的权威状态并发布包含 `selected_config_ids` 的工单载荷；不得再次初始化或重复请求复位。
6. 初始化入口必须幂等：即使测试或防御性调用重复触发，也不得重复持久化、重复 PLC 复位或重复发布不同状态。

### 管理员或工程师确认选择

1. 配置页按钮打开弹窗，并从权威状态建立草稿。
2. 用户勾选和排序，期间不修改运行状态。
3. 点击“确定”后校验非空与当前锁定状态。
4. 工厂模式控制器先验证选择是否可应用，并按下述提交语义持久化。
5. 持久化成功后，对相对旧运行选择新增的配置执行现有 PLC 启动信号复位请求。
6. 工厂模式控制器更新运行选择并发出 `factory_state_changed`。
7. `WorkOrderModule` 响应状态变化并发布新工单载荷。
8. `applied`、`restart_required` 或 `unchanged` 均视为确认完成并关闭弹窗；`restart_required` 关闭前显示现有重启提示。`rejected` 保持弹窗打开并显示错误。

### 取消选择编辑

1. 用户关闭或取消弹窗。
2. 丢弃草稿。
3. 不调用 PLC 复位、工厂状态更新、工单发布或持久化。

## 提交与持久化语义

### 普通或已准备配置范围内的提交

- 若新选择与当前权威运行选择完全相同，返回 `unchanged`，不写持久化、不复位 PLC、不发出新的状态或工单事件。
- 若生产选择租约不存在，或所选 ID 全部属于当前已准备的配置范围，则先调用现有权威选择持久化接口。
- 持久化失败时返回 `rejected`：运行选择、工厂状态和工单载荷保持旧值，弹窗保留用户草稿以便重试；不得请求 PLC 复位。
- 持久化成功后再请求新增配置的 PLC 复位并更新运行选择，返回 `applied`。
- 纯删除或纯排序不请求 PLC 复位；但成功持久化后仍更新运行选择和工单顺序。

### 需要重启的生产提交

- 当前生产组合持有选择租约且新选择包含未准备配置时，不能立即替换正在运行的生产路由。
- 控制器先把完整有序选择写入 `pending_selected_config_ids`。写入失败返回 `rejected`，运行选择、待应用选择和工单载荷均保持原值。
- 待应用写入成功后返回 `restart_required`，并将控制器的可见选择状态更新为待应用选择，同时设置 `start_ready=False` 和现有“配置已变更，请重启软件后生效。”原因；此状态用于明确阻止继续启动，不代表当前生产路由已热替换。
- `WorkOrderModule` 发布的 `selected_config_ids` 跟随该可见待应用状态，但测试启动保持被阻止，因此不会把未准备配置提交给旧生产路由。
- 该路径不写当前权威已提交选择；下次启动由唯一启动初始化流程对账待应用选择、准备新生产路由、提交权威选择并清除待应用记录。
- 在重启完成前继续编辑选择时，控制器更新同一份待应用选择；只有待应用写入成功才更新可见状态。

### 结构化结果与弹窗处理

- `applied`：持久化和运行状态均已更新，关闭弹窗。
- `restart_required`：待应用选择已可靠写入，当前启动已被阻止，显示重启提示后关闭弹窗。
- `unchanged`：没有任何副作用，关闭弹窗。
- `rejected`：没有运行状态或工单变化；保持弹窗与草稿，显示返回消息。

## 错误与边界情况

- 配置列表为空：显示空状态，不允许确认。
- 权威选择含已删除配置：打开弹窗和启动恢复时修剪失效项，并沿用现有“配置已失效”反馈。
- 配置加载或持久化失败：弹窗显示错误，事件总线继续发出可供全局状态栏消费的现有提示；提交返回 `rejected`，保留草稿且不得改变权威运行状态或工单载荷。
- 用户打开弹窗后运行阶段变为锁定状态：立即切换到只读，保留草稿供查看，但禁止确认。
- 用户打开弹窗后配置被删除或导入：重新加载列表，保留仍有效的草稿顺序，修剪失效项并给出提示。
- 用户打开弹窗后权威选择被其他事件改变：以最新权威选择重建草稿并提示用户，旧草稿不得覆盖新状态。
- 重复确认相同选择：不重复请求 PLC 复位；不产生不必要的工单变化。
- 新增配置：仅新增项触发对应 PLC 启动信号复位；删除或纯排序不触发复位，保持现有语义。

## 测试策略

- `FactoryModeController` 单元测试：启动恢复、失效修剪、去重、PLC 复位顺序、持久化成功/失败、相同选择和仅排序行为。
- 弹窗单元测试：初始快照、勾选/排序草稿、确定、取消、Escape、空选择校验、锁定阶段只读、动态配置刷新和提示。
- `WorkOrderModule` 单元测试：首页不存在配置选择控件，`value()` 与工单发布从权威状态读取选择，状态变化仍更新载荷。
- `ConfigModule` 单元测试：按钮文案和位置、打开弹窗、与当前配置脏状态相互独立、空配置行为。
- `MainWindow` 权限测试：管理员和工程师可进入配置页并使用入口；操作员主页没有入口且配置页仍不可访问。
- 回归测试：现有工厂配置列表控件、控制模块启动就绪、配置选择持久化、PLC 复位和生产组合测试继续通过。

## 验收标准

- 测试主页不显示任何可操作的配置选择列表或“配置选择”标题。
- 配置管理页显示“选择使用配置”按钮。
- 管理员/工程师可通过弹窗选择多个配置并拖拽设置首选顺序。
- 无配置时弹窗显示“配置列表为空，请先新建配置。”且不能确认。
- 取消不改变选择；确定后选择和顺序被持久化并用于后续测试。
- 操作员无法修改选择，但测试启动仍使用已保存选择。
- 活跃测试阶段不能修改选择。
- 现有启动校验、PLC 复位、工单载荷、配置失效处理和重启提示语义保持有效。

## Compatibility / Migration

- Backward compatibility: partial
- Protected surfaces: [配置选择持久化格式, `selected_config_ids` 顺序语义, 工单载荷, 启动就绪校验, PLC 启动信号复位, 配置失效处理, 生产环境重启提示, 管理员/工程师配置管理能力]
- Allowed breakage: [测试主页不再提供配置选择控件, 操作员不再能够修改配置选择, 选择从即时生效改为弹窗确认后生效]
- Migration strategy: none

现有已保存选择无需迁移；升级后按原顺序恢复。数据库、配置文件和配置包均不改变。
