# PLC 电流时频图完整链路恢复设计

日期：2026-08-28

## 背景

普通测试 PLC 可通过 `current_value_offset` 提供 Siemens `REAL` 电流值。运行时
已有完整的下游链路：`PlcCurrentCollector` 监听
`EventBus.plc_current_sampled`，把属于当前 PLC 和当前运行时间窗的样本转换为
电流轨迹，再发布 `current_trace_updated`；`StftModule` 将该轨迹绘制在时频图的
独立右侧电流坐标轴上。

当前故障是 PLC 日志能够显示电流值，但 PLC 启动测试后，时频图没有电流曲线。
调查得到以下证据：

1. 当前生产代码定义并消费 `plc_current_sampled`，但没有任何生产代码发出该
   信号。
2. 提交 `a70b17a` 在 2026-08-12 重写 `app/service/plc_service.py` 时删除了
   `_poll_current_value()` 及其 `plc_current_sampled.emit(...)` 调用。
3. 回归前实现会在每次成功读取启动位后独立读取可选电流字段，并在 PLC 网络
   往返前记录单调时间戳；电流读取失败不会阻断启动信号处理。
4. 当前 `ui/modules/stft.py`、`ui/widgets/analysis_charts.py` 和
   `app/service/current_meter_service.py` 与 `a70b17a` 的父提交内容完全一致，
   因而展示与采集器没有被该重写删除。
5. 当前采集器、运行发布与时频图展示的 62 项聚焦测试通过，说明缺口位于 PLC
   轮询到事件总线的生产边界。

## 目标

- 在保留当前 `PlcService` 结构和同事后续修改的前提下，恢复回归前的 PLC
  电流连续采样发布行为。
- PLC 启动的测试运行能够收到测试时间窗内的电流样本，并在时频图上显示完整
  电流曲线。
- 保留回归前的时间语义：采样时间戳对应本次 PLC 轮询请求的开始，而不是网络
  读取完成时间。
- 电流值 `0.0 A` 是有效样本；非数值和非有限值不发布。
- 未配置电流偏移或单次电流读取失败时，PLC 启动位检测、启动回调和后续轮询
  继续工作。
- 用自动化测试覆盖 PLC 发射端和 PLC → 采集器 → 时频图的完整链路。

## 非目标

- 不整体回滚或照抄 `a70b17a` 之前的 `plc_service.py`。
- 不撤销同事后来对 PLC 启动、工单读取、测试中信号、结果写回、自动复位、
  连接或线程模型的修改。
- 不改变 PLC 字段偏移、数据库 schema、测试配置格式或配置界面。
- 不改变当前电流曲线的颜色、线宽、坐标轴、悬停信息或分析窗口交互。
- 不让 `PlcCurrentCollector` 或 UI 直接访问 Snap7 客户端。
- 不改变独立 Modbus TCP 电流表的采集行为。

## 方案比较

### 方案 A：在当前 PLC 轮询结构中恢复独立电流发布（采用）

在当前 `PlcService.poll_once()` 中恢复一个小型 `_poll_current_value()` 边界。
它复用当前版本的偏移字典和 `read_offset_value(..., "real")`，成功后发出
`plc_current_sampled`。历史实现只作为行为和时序参考，不复制旧服务中的协议
抽象、输出线程或其他已被同事替换的代码。

该方案能恢复连续曲线，同时把改动限制在丢失的生产边界，风险最小。

### 方案 B：只在 PLC 启动上升沿读取并发布一次

当前 `_emit_plc_workorder()` 已在启动沿读取一次电流，但该读取发生在运行采集器
订阅信号之前，而且单个点不能形成测试期间的曲线，因此不能满足需求。

### 方案 C：让运行采集器直接轮询 Snap7

该方案会让不同线程或组件并发访问同一个 PLC 连接，并重复地址解析、重连和
错误处理职责，破坏当前 PLC 服务所有权，因此不采用。

## 设计

### PLC 电流轮询边界

`PlcService` 增加适配当前代码结构的 `_poll_current_value()`：

1. PLC 客户端不存在时直接返回。
2. 从当前 `_field_offsets_dict` 读取 `current_value_offset`；`None`、空字符串或
   纯空白字符串均视为未配置并直接返回。
3. 在发起 PLC 电流读取前调用 `time.monotonic()`，记录
   `sampled_monotonic`。
4. 通过当前通用读取入口 `read_offset_value(offset, "real")` 读取 Siemens
   `REAL`，不恢复旧版已经被替换的字段协议层。只有该调用抛出的
   `snap7.error.S7Error`（PLC 网络/协议错误）和 `struct.error`（返回的 REAL
   字节不足或损坏）进入可去重的外部读取错误路径。
5. `read_offset_value()` 返回后，在独立的小型 `try` 中调用 `float(raw_value)`；
   只捕获这次转换本身的 `TypeError` 和 `ValueError`。偏移解析发生在上一步函数
   内，偏移格式错误不得被这个转换捕获伪装成现场读数错误。
6. 仅有限值可发布，`0.0` 必须保留；`NaN` 和正负无穷静默丢弃。
7. 在上述捕获范围之外执行 `int(self._plc_id)`，并通过当前
   `EventBus.plc_current_sampled` 发出
   `(int(plc_id), sampled_monotonic, current_a)`。
8. 信号成功发出后清除电流读取错误去重状态。非有限值不发布，
   也不清除或替换已有错误状态，以保持回归前语义。

实现只在真实外部数据边界做上述检查，不为项目内部既定契约增加防御性兜底：

- `PlcService` 由生产组合保证持有正确的事件总线和 PLC id；直接使用
  `self.bus.plc_current_sampled.emit(...)`，不增加 `getattr`、`hasattr`、
  `callable` 或替代信号路径。
- 不重复校验已经由 PLC 配置和服务构造流程保证的字段类型、连接参数或对象
  形状。
- 不使用宽泛异常捕获包围偏移解析、PLC id 转换、信号发射、日志调用、错误
  去重状态更新或其他程序内契约；这些编程错误应立即暴露，避免被伪装成现场
  PLC 读取故障。
- 异常隔离只覆盖 `S7Error`、REAL 解码的 `struct.error` 和读取结果的
  `float()` 转换失败；不添加与本故障无关的容错层、重试、默认值或防御性
  重构。

`PlcService.__init__()` 增加仅用于该边界的 `_last_current_read_error` 状态。
重复的同一错误只写一次日志；成功读取后允许未来再次报告新的故障周期。

### 与启动轮询的时序

`poll_once()` 继续先处理断线重连，并先读取必需的启动位。启动位读取成功后，
调用 `_poll_current_value()`，然后继续现有的首次基线、上升沿、工单、启动回调
和自动复位逻辑。

该顺序保留以下性质：

- 必需启动位读取失败时沿用现有断线处理，不额外访问电流字段。
- 电流读取失败被 `_poll_current_value()` 内部隔离，不改变已读取的启动位，也
  不阻止上升沿处理。
- 触发启动的当次轮询可能早于运行采集器完成订阅；从下一轮开始的样本会被
  采集器接收，并由已有的运行起点过滤和重基准逻辑对齐到音频时间轴。
- PLC 未运行测试时仍可发出样本，但没有活动的 `PlcCurrentCollector` 消费者，
  不会产生运行轨迹或持久化数据。这与回归前行为一致。

### 采集与运行发布

保留当前 `PlcCurrentCollector` 和
`ProductionCurrentCollectorFactory` 的职责：

1. 采集器只订阅配置绑定的 `plc_id`。
2. 只接受不早于运行触发起点的单调时间戳。
3. 将时间重基准为运行开始后的秒数。
4. 每个有效样本更新轨迹并发布
   `current_trace_updated(config_id, run_id, payload)`。
5. 运行结束后停止订阅并沿用当前持久化、统计和回放数据路径。

若测试没有揭示当前下游实现与本规格冲突，则不修改这些生产文件。

### 时频图展示

回归前最后一个工作版本与当前展示代码完全一致，因此“恢复之前的完整展示”
定义为恢复其输入数据后继续使用现有展示契约：

- 电流轨迹覆盖在 STFT 图像上，并使用独立的右侧电流坐标轴。
- 保持当前粉色、线宽 `1.5` 的曲线样式。
- 运行期间接收增量轨迹时只更新电流曲线，不重绘已有热力图。
- 电流早于首个 STFT 帧到达时先按运行 ID 缓存，首帧出现后显示。
- 只显示当前配置、当前运行的电流；切换运行时清除陈旧轨迹。
- 切换展示通道时，同一运行的电流轨迹保持可见。
- 进入复核、选择分析窗口和悬停评分时沿用现有电流显示行为。

不会为了制造展示侧代码差异而修改已经等同于回归前版本的 UI。完整链路测试
将证明恢复后的 PLC 样本能够实际到达该展示契约。

## 错误处理与日志

- 未配置 `current_value_offset` 是正常配置，不记录警告或错误。
- 单次电流字段读取异常、类型转换异常或非有限值不会断开 PLC，也不会阻止
  启动检测。
- 可报告错误应包含 PLC id、字段名 `current_value_offset` 和具体原因。
- 连续重复的同一电流读取错误只记录一次；成功样本会重置去重状态。
- 非数字类型转换失败属于可报告错误并参与去重；`NaN` 和正负无穷属于 PLC
  暂态无效样本，静默丢弃且不改变错误去重状态。
- 偏移格式错误、总线缺少信号、PLC id 违反生产构造契约、信号槽异常或其他
  非 `S7Error`/`struct.error` 的意外程序异常不伪装成电流读取错误；这些程序
  配置/编程错误原样向外暴露。
- 启动位读取错误仍保持当前行为，因为启动位是必需字段，不属于可选电流
  错误隔离范围。

## 测试策略

### PLC 服务单元测试

恢复或按当前接口重写历史 `tests/test_plc_service_current.py` 覆盖：

- 已配置电流偏移时，每次成功轮询发出正确 PLC id、读取前单调时间戳和
  `REAL` 电流值。
- `0.0` 被发布，不因布尔判断而丢失。
- 未配置、空白偏移时不读取电流、不发信号、不记录错误。
- 非数字值不发布，记录包含 PLC id、字段名和原因的去重错误。
- `NaN` 和正负无穷不发布、不记录新错误，也不清除已有错误去重状态。
- 电流读取异常不阻止同一次轮询的启动上升沿回调。
- 同一异常连续出现只记录一次；成功后再次失败可再次记录。
- 不增加任何针对内部总线或 PLC id 的生产校验、默认值或兜底。
- 用一个聚焦的参数化契约测试证明以下错误原样向外暴露，且不会写 PLC 电流
  错误日志或改变 `_last_current_read_error`：非法偏移导致的解析异常、非法
  PLC id、缺少 `plc_current_sampled`、`emit()` 主动抛出的异常，以及从
  `read_offset_value()` 冒出的非 `S7Error`/`struct.error` 意外程序异常。该
  测试只锁定捕获边界，不对应任何新增生产分支或防御性校验。

### 受保护 PLC 轮询顺序回归测试

当前分支在同事重写后删除了历史 `test_plc_service*.py`，因此必须恢复或按当前
接口重建测试，而不能把“运行已有 PLC 测试”作为保护依据。至少覆盖：

- 首次读取启动位只建立基线，不调用启动回调。
- 后续 `False -> True` 上升沿依次保留当前“写测试中、记录触发时钟、读取工单、
  调用启动回调、按配置自动复位”行为。
- 未配置电流时，上述现有调用和参数完全不变。
- 已配置电流且读取成功、转换失败或抛出异常时，上升沿回调、测试中写入和
  自动复位仍各执行一次。
- 未连接时仍只走当前重连路径，不尝试电流读取或启动处理。
- 启动位读取失败时仍沿用当前失败路径，不尝试电流读取或启动回调。

测试使用假 Snap7 客户端和调用记录器断言可观察顺序，不把旧版内部方法或旧
线程模型重新定义为生产契约。

测试必须先在当前代码上失败，以证明它捕获的是缺失的生产发射端；最小实现
完成后再转绿。

### 完整展示链路回归测试

增加一个使用同一 `EventBus` 的启动边界集成测试，串联：

1. 带假 Snap7 客户端的 `PlcService`；
2. 首次 `False` 轮询建立启动位基线；
3. 第二次 `True` 轮询检测上升沿；该轮电流发布发生在订阅前，应被安全忽略；
4. `on_start_requested` 测试回调模拟已接受生产启动，使用
   `ProductionCurrentCollectorFactory` 创建并启动绑定相同 PLC id、config id
   和 run id 的生产采集器，同时建立 STFT 运行上下文；
5. 下一次 PLC 轮询发布首个可消费电流样本，经生产
   `current_trace_updated` 回调进入已收到 STFT 帧的 `StftModule`。

处理 Qt 事件后，断言时频图 `current_trace_payload()` 只包含订阅后的样本，
其时间与运行触发起点一致；订阅前的启动沿样本不得错误进入运行。该测试还要
证明其他 PLC id 不会污染当前图，并在测试结束时停止采集器、关闭 UI，避免
信号或 Qt 对象泄漏。

现有 `test_current_meter_service.py`、生产组合电流发布测试和
`test_live_current_trace.py` 继续作为各层详细契约测试。

## Compatibility / Migration

- Backward compatibility: required
- Protected surfaces: [PLC 启动上升沿检测、PLC 工单读取、测试中状态写回、测试结果写回、启动位自动复位、PLC 连接与重连、PLC 字段偏移配置、Modbus TCP 电流采集、STFT 电流曲线样式与交互、运行电流持久化]
- Allowed breakage: []
- Migration strategy: none

本修复不修改数据库或配置格式。未配置 PLC 电流的部署保持原行为；已配置
`current_value_offset` 且测试配置选择 `source=plc` 的部署恢复回归前行为。

## 验收标准

1. PLC 连续轮询可选 `current_value_offset` 并发出带读取前单调时间戳的有限
   电流样本，包括 `0.0 A`。
2. PLC 启动测试后，属于该 PLC、配置和运行时间窗的电流样本形成轨迹，并在
   时频图当前粉色右轴曲线上显示。
3. 电流曲线与运行时间轴对齐，首个可用样本不会因发生在运行起点之后而整体
   丢失。
4. 未配置或读取失败的电流字段不阻止启动检测、工单读取、启动回调、自动复位
   或后续轮询。
5. 连续重复的电流读取错误不会刷屏，恢复后再次发生的错误仍可报告。
6. 当前 PLC 服务中同事后续修改的非电流行为没有被旧代码覆盖或回滚。
7. UI 样式和交互保持回归前最后工作版本；端到端测试证明 PLC 样本实际到达
   STFT 电流图层。
8. 聚焦测试和完整测试套件通过，最终差异不包含数据库、配置格式或无关重构。
9. 修复没有引入超出外部 PLC 值边界的冗余校验、默认值、异常吞噬或防御性
   抽象；内部契约错误仍能直接暴露。
