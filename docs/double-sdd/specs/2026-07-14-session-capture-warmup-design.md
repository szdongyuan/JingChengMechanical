# 测试会话 50ms 统一预热设计

## 背景

实时测试开始后的最初 `0.05s` 属于设备与信号链预热阶段，不应参与任何用户可感知或可持久化的数据流程。当前实时音频从第一个采集块开始直接进入监听和实时分析，最终录音缓冲也从会话接入录音器的起点直接保存；电流表则使用独立的单调时钟起点。

软件支持多个测试配置在不同时间接入同一个共享录音器，因此预热边界必须属于测试会话，不能属于物理录音器全局。

## 用户可见行为

- 开始指令以及 PLC/UI 的“运行中”状态立即响应。
- 每个实时测试会话开始后先经历 `0.05s` 数据预热期。
- 预热期内：
  - 监听不得播放真实采集数据；
  - 实时音频、振动和电流分析不得收到有效数据；
  - 录音进度保持 `0s`；
  - 不生成可保存或可复核的数据。
- 预热结束的瞬间定义为该会话有效数据的 `0s`。
- 配置录音时长代表预热后的完整有效时长。例如配置 `5s` 时，物理采集至少覆盖 `5.05s`，最终有效缓冲和完整 WAV 仍为 `5s`。
- 分析窗口偏移、手动复核选择、回放以及图表横轴均相对于新的 `0s`。
- STFT、振动等窗口型指标的第一个实际数据点可以自然晚于 `0s`，但其计算输入不得包含预热样本。
- 电流表早于预热截止时刻的读数被丢弃；后续读数减去预热截止时刻后进入新时间轴。由于轮询间隔和读取耗时，第一个电流点可以晚于 `0s`，不得人为补造 `0s` 数据点。
- 如果在预热结束前停止，不保存 WAV、不创建音频数据库记录、不运行分析，也不产生复核或回放数据。
- 如果在预热结束后提前停止，保存已经取得的有效数据；是否分析继续遵循现有不完整录音规则：必须启用“不完整录音分析”，且有效片段覆盖配置分析窗口，否则仅停止并保存，不产生分析结果。

## 范围

本设计适用于实时测试采集链路：

- 共享音频录音器接入；
- 实时监听；
- 实时 SPL、FFT、STFT、响度及其他音频派生分析；
- 振动通道分析；
- Modbus 电流表实时曲线与复核数据；
- 完整录音和提前停止录音的保存；
- 最终判定、图表、手动复核、重放和数据导出所使用的新录音。

## 非目标

- 不裁剪“导入音频分析”的外部 WAV。
- 不裁剪或修改黄金样本导入。
- 不迁移、重写或标记已有录音；用户确认已有录音已经符合预期。
- 不改变配置文件、数据库表结构或用户配置项。
- 不强制将 STFT、振动等窗口中心时间戳改写为 `0s`。
- 不重构与本功能无关的 DSP 算法或图表样式。

## 现状与约束

### 共享录音器

`AudioRecorder` 当前以约 `0.05s` 为一个采集块，向监听和 `TestSession` 分别广播同一原始块。`RecorderAttachSnapshot` 为晚加入的会话记录已发出的样本边界，最终缓冲通过该快照切片。

当前块事件只有数据和块序号；`TestSession` 通过“相对块数 × 最大块长度”估算进度。最后一个部分块以及采集和发出之间的排队可能使该估算与真实样本范围不一致，因此不能把“跳过第一个块”作为预热实现。

### 监听旁路

监听目前直接订阅录音器原始块，与 `TestSession` 的接入等待和最终缓冲切片相互独立。若只在分析或保存前裁剪，监听仍会泄漏预热数据。

### 电流表

`CurrentMeterCollector` 当前在自身启动时建立 `time.monotonic()` 起点，采样完成时间相对于该起点记录。它与音频会话的样本边界不是同一时间域，必须显式使用会话预热截止时刻进行过滤和重定位。

## 方案选择

### 采用：每会话唯一采集窗口

保持共享录音器为原始采集源，为每个测试会话创建独立的 `SessionCaptureWindow`。它拥有该会话的接入边界、预热范围、有效范围、有效计数和重定位时间轴，并且是监听、实时分析和最终缓冲的唯一数据入口。

### 不采用：录音器全局裁剪

全局裁剪只能正确处理物理录音器的第一个会话。晚加入共享录音器的配置需要从自己的接入时刻重新预热，无法共享一个全局裁剪边界。

### 不采用：在每个下游出口分别裁剪

分别修改监听、分析、保存、回放和图表容易漏掉路径、使用不同舍入方式或对已裁剪缓冲再次裁剪，无法形成可验证的不变量。

## 详细设计

### 1. 统一常量与样本换算

定义唯一常量：

```text
SESSION_WARMUP_SECONDS = 0.05
```

预热样本数采用向上取整：

```text
warmup_samples = ceil(sample_rate * SESSION_WARMUP_SECONDS)
```

这保证任意有效采样率下都不会纳入时间严格早于 `0.05s` 的样本。配置有效时长的目标样本数同样向上取整，确保最终有效时长不短于配置值：

```text
target_samples = ceil(sample_rate * record_duration)
```

所有通道沿样本轴使用相同边界；不得按通道单独裁剪。

### 2. 录音器提供真实绝对样本范围

录音器必须为每个实际采集块分配单调、不重叠的绝对半开样本范围 `[sample_start, sample_end)`。范围在 PortAudio 回调接收块时确定，而不是在后台线程稍后处理或发出块时推算，从而排除队列积压造成的接入竞态。

会话接入请求不得直接把“当前已发出样本游标”和请求时的 `time.monotonic()` 拼成一个快照，因为两者可能来自不同物理时刻。录音器应记录请求的单调时刻，并把请求登记为待解析请求。录音器随后使用第一个映射后 ADC 时间范围结束时刻不早于请求时刻的 PortAudio 回调块，将请求原子地解析为：

- 该块内时间不早于请求时刻的第一个绝对采集样本；
- 与该样本对应的单调时钟时刻；
- 为预热样本和完整有效样本保留足够录音器容量。

回调块的单调时钟范围应由同一次回调取得。优先利用 PortAudio `time_info` 的 ADC/当前流时钟差，并在回调入口采集 `time.monotonic()` 完成时钟域映射。设映射后的块范围为 `[block_time_start, block_time_end)`、样本范围为 `[block_sample_start, block_sample_end)`，则仅当 `request_time <= block_time_end` 时解析请求，并使用：

```text
offset = ceil((request_time - block_time_start) * sample_rate)
offset = clamp(offset, 0, block_frame_count)
attach_sample = block_sample_start + offset
resolved_attach_monotonic_time = block_time_start + offset / sample_rate
```

这保证接入样本不早于请求时刻。若请求晚于该块的 ADC 结束时刻，即使回调函数在请求后才进入，也必须等待后续块，不得把已经由硬件取得的旧块归入新会话。

若设备未提供可用的 ADC/流时间信息，不得通过“回调时刻减块时长”反推块时间范围，因为回调调度延迟未知。降级路径必须保守地排除整个当前块，并在块末建立：

```text
attach_sample = block_sample_end
resolved_attach_monotonic_time = max(request_time, callback_monotonic_time)
```

该路径需要记录一次降级日志。它可能额外丢弃不到一个回调块，并使电流有效时钟相对音频更保守，但保证请求前样本不会进入预热或有效数据。

若接入请求落在回调块 ADC 时间范围内部，允许从块中间的精确样本边界建立会话；该块在进入会话窗口时按此边界切片。接入登记与回调范围分配使用同一把录音器状态锁，使每个请求只能解析一次。新录音器尚未产生回调时，请求保持待解析状态。`TestSession`、监听和电流实时发布在快照解析前都不得接收有效数据。

录音器发给会话窗口的事件必须携带准确的绝对样本范围。不得通过块序号或“最大已见块长度”重建范围，也不得把最后一个部分块扩展为包含旧样本的重叠尾块。

### 3. `SessionCaptureWindow` 不变量

每个会话窗口由以下边界定义：

```text
attach_sample
retained_start = attach_sample + warmup_samples
retained_end = retained_start + target_samples
```

窗口接收原始绝对样本块时：

- 完全位于 `retained_start` 前的块被丢弃；
- 跨越 `retained_start` 的块在精确样本边界切开；
- 有效块被裁剪到 `retained_end`；
- 对外样本范围重定位为从 `0` 开始的连续半开范围；
- 每个有效样本最多对外发出一次；
- 窗口关闭后不再接收共享录音器的后续样本。

窗口拥有唯一的有效样本计数。进度、完成条件和实时 DSP 时间均由有效样本计数除以采样率得到，不再使用原始块序号估算。

### 4. 唯一实时扇出

录音器原始块不得再分别直连监听和 `TestSession`。所有会话下游必须订阅 `SessionCaptureWindow` 的有效输出：

```text
共享原始录音器
  -> SessionCaptureWindow
       -> 监听
       -> 实时分析/图表
       -> 有效进度与完成判定
```

预热期内监听只能保持静音或尚未开始播放，不得通过填充、预缓冲或错误恢复逻辑播放真实预热样本。若监听输出线程在预热期已启动，其静音行为不得产生误导性的持续 underrun 错误。

实时分析接收的第一个样本范围从 `0` 开始。队列溢出等现有显示降级可以继续丢弃显示工作，但不能改变会话窗口的有效样本边界或最终保存缓冲。

### 5. 完整时长与共享容量

会话接入请求一经登记，即成为共享录音器的活动容量所有者，即使其精确 `attach_sample` 尚未解析。存在待解析所有者时，录音器不得因为当前固定容量已满而发出全局完成或关闭输入流；写入新回调块前必须按需扩展原始缓冲。

请求解析后，为该所有者记录精确的 `retained_end = attach_sample + warmup_samples + target_samples`。会话仅在累计取得 `target_samples` 个有效样本后完成。

一个会话完成或停止时释放自己的容量所有权，但不得终止仍被其他已解析或待解析会话使用的共享录音器。共享录音器只有在不存在待解析所有者，且绝对采集游标达到所有已解析活动所有者中最晚的 `retained_end` 时，才可以判定全局采集完成。若录音器已经不可继续接收新所有者，管理器必须创建新的录音器，而不是把新会话接到已停止实例。

### 6. 最终缓冲、保存和后续消费者

完整结束或提前停止时，最终缓冲必须使用与实时窗口相同的绝对有效范围提取，不得在 `_save_wav`、判定、图表、复核或回放层再次裁剪。

提取顺序为：

1. 从共享原始缓冲取得该会话已经存在的有效绝对范围；
2. 裁剪到窗口冻结时的有效结束边界；
3. 投影配置选择的通道；
4. 将所得缓冲作为会话的规范 `0s` 缓冲；
5. 保存、判定、AI、图表、复核和回放全部使用该规范缓冲。

完整结束时规范缓冲恰好包含 `target_samples` 帧。提前停止时可以更短，但首帧仍对应新 `0s`。

已保存 WAV 的首帧已经是有效 `0s`，数据管理播放、历史统计和导出不得再裁剪。

### 7. 电流表门控与重定位

会话快照由录音器在未来回调边界解析后，使用其中与 `attach_sample` 同源的单调时钟起点建立预热截止时刻：

```text
current_epoch = resolved_attach_monotonic_time + SESSION_WARMUP_SECONDS
```

电流采集可以在会话开始时启动并暂存带绝对单调完成时刻的读数，但在录音器解析会话快照前不得发布。快照解析后：

- 完成时间早于 `current_epoch` 的读数不得写入有效样本集合，也不得触发实时曲线更新；
- 保留读数的时间为 `sample_monotonic_time - current_epoch`；
- 停止后复核使用的电流样本必须与实时曲线使用同一已门控集合；
- 不人为插值或补造 `0s` 点；
- 预热期内停止时清除所有暂存电流读数。

该方案保留 Modbus 轮询和网络读取本身的延迟；它只统一时间原点，不声称电流读数与音频样本达到亚毫秒硬件同步。

### 8. 状态、进度与停止

- PLC/UI 开始接受状态保持现有立即响应语义。
- 预热期间有效进度为 `0`。
- 预热结束后进度从首个有效样本开始累计。
- 完整运行的结果产生时间相对当前行为延后约 `0.05s`。
- 在取得首个有效音频样本前停止：关闭窗口，停止监听和电流采集，不保存、不分析、不创建复核或回放状态。
- 在取得有效样本后停止：冻结窗口并保存现有规范有效缓冲。只有配置启用了现有不完整录音分析，并且缓冲覆盖配置分析窗口时才运行分析；否则保持“已停止、无分析结果”。

### 9. 分析窗口和时间轴

配置的 `analysis_window_offset_ms`、`analysis_duration`、手动复核选择和回放选择继续使用现有接口，但都解释为规范缓冲的新时间轴。

所有基于规范缓冲重新计算的 SPL、响度、STFT、FFT、振动和评分自然排除预热样本。图表范围从 `0s` 开始；窗口型算法的第一个数据点保留其真实窗口中心或结束时间，不进行伪造的零点平移。

## 错误与边界处理

- 无效或非正采样率继续按现有启动错误处理，不创建窗口。
- 任意块大小、最后部分块和跨预热边界块均使用绝对样本范围裁剪。
- 预热样本数可能大于一个采集块，不假设“一个块等于 50ms”。
- 录音器队列积压时，接入前已经由硬件取得的块不得算作接入后的预热或有效数据。
- 监听初始化失败继续按现有清理语义处理，不能退回到原始块旁路。
- 预热期停止不允许创建零长度 WAV 或孤立数据库记录。

## 测试策略

### 样本窗口单元测试

- 常见采样率 `44.1kHz`、`48kHz` 以及乘积非整数的采样率使用向上取整。
- 完全位于预热前、正好结束于边界、跨越边界和正好开始于边界的块。
- 不同块大小和最后部分块。
- 有效输出样本范围从 `0` 连续递增且无重复、无缺口。
- 输出严格停止在 `target_samples`。

### 共享录音器与晚接入

- 两个会话在不同绝对样本处接入，各自独立丢弃自己的前 `0.05s`。
- 晚接入会话获得完整配置有效时长。
- 一个会话完成或停止不截断另一个会话。
- 接入发生在采集与后台发出之间时，接入前块不会泄漏。
- 新录音器启动有延迟时，音频样本边界和电流预热截止仍由首个可解析回调中的同一样本时刻建立。
- 接入请求落在 ADC 块内部时，使用带标记样本验证块前部被排除、首个不早于请求的样本被保留为预热起点。
- 晚接入发生在两个回调之间或与回调并发时，样本与单调时钟快照不会错配。
- 共享录音器到达原容量末端且最后块已经排队时，新待解析会话会阻止提前完成，并在回调到达后获得完整容量。
- 设备缺少 ADC 时间信息时，降级路径会排除带标记的整个当前块，且建立的单调时钟不早于请求时刻。

### 监听与实时分析

- 预热块不进入监听缓冲。
- 第一个跨界块只向监听发送有效后半段。
- 实时分析的首个重定位样本范围从 `0` 开始。
- 预热期间不发出有效分析帧，进度保持 `0`。

### 保存、判定与回放

- 配置 `5s` 最终 WAV 精确包含目标有效帧数，且首帧是预热边界后的标记样本。
- 保存层不执行第二次裁剪。
- 判定、图表、手动复核和重放的时间选择相对于新 `0s`。
- 部分停止只保存预热后的有效片段。
- 预热期停止不调用保存、分析或数据库写入。
- 预热后提前停止分别覆盖“不完整分析已启用且窗口充分”和“未启用或窗口不足”两类现有行为。

### 电流表

- 预热截止前读数不保存、不实时发布。
- 截止时刻及之后读数以截止时刻为 `0s` 重定位。
- 第一个点允许晚于 `0s`，不补点。
- 实时与停止后复核使用相同集合和时间轴。

### 明确不变的入口

- 导入音频分析仍从外部 WAV 原始 `0s` 处理。
- 黄金样本导入不应用会话预热。
- 已保存规范 WAV 的播放、历史统计和导出不再次裁剪。

## Compatibility / Migration

- Backward compatibility: partial
- Protected surfaces: [配置文件格式、数据库表结构、PLC/UI 立即开始响应、导入音频语义、黄金样本语义、已保存 WAV 不重复裁剪]
- Allowed breakage: [实时测试完成时间延后约 0.05s、预热期间进度保持 0、预热期停止不再产生部分 WAV]
- Migration strategy: none
