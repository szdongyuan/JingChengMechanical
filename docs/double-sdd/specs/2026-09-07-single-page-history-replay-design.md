# 历史回放单页简化设计（已获用户确认）

## 范围及优先级

这是已实现的历史分析回放功能的用户反馈调整。用户明确要求：不要结果/试听两个页面；同一界面保留已保存结果和重新标记，试听仅提供通道选择、增益和重放按钮。用户进一步确认默认优先 CH1，不存在 CH1 则选录音保存的第一个可用通道；点击重放播放所选通道的完整录音。

本设计覆盖 `2026-09-07-historical-analysis-replay-design.md` 中历史窗口试听分页面、波形、片段选择及多通道混播的要求。其余已保存结果读取、人工标记、数据管理入口和隔离保证不变。用户此前要求计划审查通过后直接实施，不重复请求实施许可。

## 设计

- 历史窗口取消 QTabWidget。顶部保留记录信息、当前人工标记、刷新、保存标记和关闭；相邻的一行紧凑控件为「通道 [单选下拉框] 增益(dB) [数值] [重放]」。下方直接显示原始已保存结果和配置对应图表。
- 不再创建历史窗口的试听波形、试听 STFT 或框选控件，也不创建隐藏的旧试听面板。打开窗口只加载已有结果及音频元数据，不为试听预读整段 WAV 或计算图形。
- 通道选项取持久化 `audio.channel_order`，显示物理 CH 编号（存储值 + 1）。默认优先物理索引 0，否则取 channel_order 第一项。用户仅能选一个通道。
- 增益默认沿用当前 20 dB，允许范围沿用 -60 到 35 dB。点击「重放」后以所选物理通道、当前增益、0 到 frame_count/sample_rate_hz 的完整时长调用现有 run-scoped playback。再次点击从头重放；启动任务未结束时禁用按钮，避免并发重复请求。没有单独暂停、停止、进度或片段操作；关闭窗口/刷新仍停止自身拥有的播放。
- 播放读取和启动继续后台执行，控件只在 GUI 线程更新；沿用已有 owner token、worker 存活和关闭期间迟到启动清理机制。关闭旧窗口不得中断后来由别的窗口接管的播放。没有新录音或分析执行。
- 录音缺失或播放服务不可用时提示并禁用重放，不妨碍查看结果或重新标记。重新标记仅修改人工判定，不改原始结果/音频。
- 现有数据管理表中的旧「回放」入口及其独立试听窗口保持兼容；本次只简化新增的「查看分析结果」历史窗口，不改实时界面。

## 方案取舍

采用不含图形的轻量重放控件，复用已有后台播放与归属清理帮助函数。相比直接隐藏旧面板，它不会多做 WAV 读取及 STFT；相比重做播放服务，它保持当前音频实现及并发规则。

## Compatibility / Migration

- Backward compatibility: required，除用户明确要求替换的历史窗口双页试听交互。
- Protected surfaces: 数据库、结果/音频文件、标记规则、既有数据管理操作、旧回放入口、实时结果页、录音及 PLC、播放后端/API。
- Allowed breakage: 新历史窗口不再提供标签页切换、多选混播、试听图形及片段播放；相关内部 UI 测试更新为新交互。
- Migration strategy: none。继续在现有 `codex/historical-analysis-replay` 工作区迭代，主目录不合并，不结束用户当前运行的程序。

## 验收

1. 历史窗口没有标签页和额外试听图形；结果、重新标记及紧凑重放操作同时可见，APP_QSS 下不裁切。
2. channel_order=(3,0,1) 默认 CH1；(3,1) 默认 CH4；切换通道后请求携带正确 run_id 和物理索引、单通道、完整时长及增益。
3. 打开窗口不调用 WAV 加载或试听 DSP；只有点击重放才请求现有播放服务。界面不因播放启动阻塞。
4. 关闭/刷新/拒绝期间后台任务正确清理；先后窗口不串播放归属。无音频、启动失败有正确可见状态，不影响结果/标记。
5. 回归真实数据库读取与标记、原始数据不变、数据管理入口、旧回放面板/播放服务；更新单页截图。
