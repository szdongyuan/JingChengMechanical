# PLC 工单单列分组布局设计规格

## 背景

测试主页“工单”卡片当前把 PLC 信息按两列排列。每个 PLC 自身包含两行：上方为 SN 码，下方为型号；当存在 PLC1 和 PLC2 时，两组信息左右并列，字段密度较高且两组之间缺少清晰但克制的视觉边界。

## 目标

- 将 PLC 信息改为单列纵向分组。
- 每个 PLC 继续使用两行：第一行 SN 码，第二行型号。
- 两个 PLC 时形成四行字段。
- 相邻 PLC 分组之间增加轻量横向分隔线和少量垂直留白。
- 支持任意数量的已配置 PLC，按相同规则继续向下排列。

## 非目标

- 不改变 PLC 的发现、排序、增删或数据读取逻辑。
- 不改变 SN、型号的缓存、刷新或蓝色高亮行为。
- 不改变只读属性、“未读取”占位文案或工单事件载荷。
- 不限制最多显示两个 PLC。
- 不调整主页其他卡片或配置选择弹窗。

## 界面设计

### PLC 分组

- 所有 PLC 按现有升序顺序显示。
- 每个 PLC 分组占据工单卡片的完整可用宽度。
- 分组内部为两行网格：
  - 第 1 行：`PLCn SN码` 标签和对应只读输入框；
  - 第 2 行：`PLCn 型号` 标签和对应只读输入框。
- 标签沿用现有固定宽度；输入框横向扩展填满剩余空间。
- 输入框高度继续限制为 28–30 px，只读状态、占位文字和已有高亮行为保持不变。
- SN 与型号输入框必须设置对象名 `PlcField`，复用全局 `QLineEdit#PlcField` 样式的 `padding: 4px 8px`，不得继续套用普通 `QLineEdit` 的 `padding: 8px 10px`。
- 不通过增加输入框高度解决文字裁切；在 Windows 当前字体度量下，`PlcField` 的内容矩形高度必须大于字体高度，并为文字上下保留可见余量，使“未读取”和实际值的下沿完整显示。

### 分隔线

- 在相邻 PLC 分组之间插入一条水平分隔线。
- 第一组之前和最后一组之后不显示分隔线。
- 分隔线必须使用对象名 `plc_group_separator`。
- 分隔线使用 `QFrame.Shape.HLine`、`QFrame.Shadow.Plain`、`lineWidth=1` 和颜色 `#e2e8f0`。
- 分隔线控件固定高度为 13 px；水平线绘制在控件垂直中心，因此视觉上形成 1 px 线条和上下各 6 px 留白。
- 分隔线横向填满 PLC 信息区；它只提供轻微分界，不形成独立卡片或强边框。
- 分隔线不接收焦点、不参与数据映射，也不改变 PLC 行的伸缩行为。

### 视口与滚动

- PLC 信息区放入无边框、可自动调整内容宽度的 `QScrollArea`，对象名为 `plc_workorder_scroll_area`。
- 水平滚动条始终关闭。
- 当 PLC 数量为 0、1 或 2 时，纵向滚动条策略强制为 `ScrollBarAlwaysOff`；正常主页卡片高度必须完整显示两个 PLC 的四行字段及中间分隔线。
- 当 PLC 数量大于 2 时，纵向滚动条策略切换为 `ScrollBarAsNeeded`；只有内容实际超过视口时才显示。
- 滚动仅作用于 PLC 分组区域；下方“当前阶段”标签位于滚动区之外，始终固定可见。
- PLC 增删后必须同步更新滚动条策略和内容尺寸，不能残留不需要的滚动条。

### 动态数量与空状态

- 两个 PLC 时顺序为：PLC1 SN、PLC1 型号、分隔线、PLC2 SN、PLC2 型号。
- 三个及以上 PLC 时，每新增一个 PLC 都追加两行，并仅在相邻分组之间追加一条分隔线。
- 没有已配置或可显示 PLC 时，继续显示现有“未配置 PLC”空状态，不显示分隔线。
- PLC 增删导致布局重建时，分隔线数量始终为 `max(PLC 数量 - 1, 0)`。

## 组件与实现边界

### `WorkOrderModule`

- 保留现有 `plc_sn_widget` 和 `plc_sn_layout` 容器。
- 新增 `plc_workorder_scroll_area` 作为 `plc_sn_widget` 的父视口；模块外层布局添加滚动区后，再添加固定的阶段标签。
- `_rebuild_plc_sn_rows()` 继续负责销毁旧布局项、创建字段控件以及维护 `_plc_sn_edits`、`_plc_model_edits` 映射。
- `plc_sn_layout` 改为只有第 0 列参与伸缩，`columnStretch(0)=1`，不再保留第二个伸缩列。
- 每个 PLC 的两行字段容器按顺序添加到外层网格的 `(outer_row, 0, 1, 1)`，即占据唯一列的完整宽度，不再按 `index // 2, index % 2` 分配到两列。
- 相邻分组之间的 `plc_group_separator` 同样添加到 `(outer_row, 0, 1, 1)`，与分组使用相同的全宽列跨度。
- 数据更新方法 `_refresh_plc_sn_rows()` 不改变；它仍按 PLC ID 更新现有输入框。

## 数据与事件流

本改动不改变数据流：

1. PLC 列表变化触发 `_refresh_plc_sn_rows()`。
2. PLC ID 集合变化时重建纵向分组和分隔线。
3. SN/型号事件继续写入按 PLC ID 缓存的值。
4. 刷新过程继续把缓存值同步到对应只读输入框。

## 样式回归边界

- `PlcField` 是项目已有的紧凑 PLC 字段样式；本改动只为两个只读输入框绑定该对象名，不新增或覆盖全局 QSS。
- 如果平台字体或样式发生变化，输入框测试必须以字体度量和内容矩形为依据检测裁切风险，不能只断言固定控件高度。

## 测试策略

- 验证两个 PLC 生成两个全宽纵向分组，而不是左右两列。
- 验证每个分组内部 SN 位于第 1 行、型号位于第 2 行。
- 验证两个 PLC 恰好生成一条分隔线，并位于两组之间。
- 参数化验证 0、1、2、3 个 PLC 时分隔线数量分别为 0、0、1、2。
- 验证外层布局只有一个伸缩列，所有 PLC 分组和分隔线均位于第 0 列且占据完整可用宽度。
- 验证两个 PLC 在正常工单卡片高度下纵向滚动条不可见且 `maximum()==0`。
- 验证三个及以上 PLC 在受限视口高度下纵向滚动条可用、`maximum()>0`，同时阶段标签仍在滚动区外可见。
- 验证 PLC 增删后的映射、排序、缓存值、只读属性、“未读取”占位和 SN 蓝色高亮行为不回归。
- 验证 SN 与型号输入框对象名均为 `PlcField`，并继续保持 28–30 px 高度。
- 在应用 `APP_QSS` 的真实 Qt 样式环境中，使用 `QStyle.SubElement.SE_LineEditContents` 获取内容矩形，验证其高度至少比 `fontMetrics().height()` 多 2 px；该断言覆盖截图中“未读取”下沿被截断的回归。
- 运行 `tests/test_workorder_module.py` 以及受工单模块影响的控制模块测试。

## 验收标准

- 截图中的两个 PLC 不再左右并列，而是上下排列。
- 每个 PLC 的 SN 和型号仍上下排列，因此两个 PLC 共四行。
- 第 2 行和第 3 行之间存在一条轻量横向分隔线和少量留白。
- 三个及以上 PLC 按同一规则向下扩展。
- 两个 PLC 时不显示滚动条；更多 PLC 仅在内容超出 PLC 信息视口时按需滚动。
- “当前阶段”不随 PLC 信息滚动。
- 所有现有 PLC 数据刷新和视觉状态保持有效。
- “未读取”和实际 SN/型号文字上下完整显示，下沿不被输入框裁切。

## Compatibility / Migration

- Backward compatibility: required
- Protected surfaces: [PLC 排序, PLC 动态数量, SN/型号数据映射, 工单事件, 只读状态, 未读取占位, SN 高亮, 无 PLC 空状态]
- Allowed breakage: [PLC 信息由双列展示改为单列纵向展示]
- Migration strategy: none

本改动仅调整运行时界面布局，不修改数据库、设置文件、配置格式或持久化数据。
